# Web UI 功能规格

> 细化 [architecture.md § 2.3](../architecture.md#23-客户端) 和 [roadmap.md](../roadmap.md) 的 Web UI 条目。路由、布局、每个页面的内容、模型 / 思考 / 权限模式的选择方式、状态层和缓存。组件级视觉规范另写 `web/DESIGN.md`。

## 1. 定位

**手机上能用，桌面上好用。** 典型场景是在手机上给家里的机器发一句话、过十分钟回来看结果、点一下审批。桌面上则是开着一个会话长时间跟进。

**给开发者用，体验对齐 Claude 桌面版**（[ADR-34](../decisions.md#adr-34-web-ui-是开发者客户端体验对齐-claude-桌面版每个会话可以有自己的-worktree)）：登录、配对、项目、会话、审批、设置之外，每个会话可以在自己的 git worktree 和分支里工作，会话页能看相对 base 的改动、同步 base、让 agent 提交和开 PR、看 PR 状态。hub 只管连通性，这些都经 E2E 走 daemon。

不做：终端、远程 shell、编辑器（diff 只读，改代码交给 agent）、经 hub 明文反代 dev server。dev server 预览走 Noise 隧道，在独立的预览 origin 里跑（§ 13，[ADR-39](../decisions.md#adr-39-预览-dev-servernoise-隧道里的端口转发)）。

## 2. 路由

TanStack Router，文件式路由。`:node` 是 daemon 的 DeviceId，URL 里用前 8 位短 id，冲突时回退全长。

| 路由 | 页面 | 需要 |
|---|---|---|
| `/login` | 登录 | 无 |
| `/invite/:code` | 邀请落地。`single`：存 code 到 sessionStorage，转 `/login`。`multi` 没有邀请：显示「注册是开放的」，按钮去 `/login`，不存 code | 无 |
| `/auth/callback/:provider` | 不是 Web UI 的路由：OAuth 回调由 hub 处理并 302，成功回 `next` 或 `/settings/login?linked=<p>`，失败回 `/login?oauth_error=<code>&provider=<p>` 或 `/settings/login?...`（§ 4.1、§ 4.9） | — |
| `/` | 重定向：这个浏览器有已配对的节点 → `/inbox`；没有，但账号下有节点 → `/unlock`；账号下也没有 → `/setup` | 登录 |
| `/inbox` | 待处理，应用的首页（[§ 4.11](#411-待处理-inbox)）。`?node=<短 id>&session=<会话 id>`：从权限请求的推送或 toast 点进来，定位并展开那个会话最早的一条待答复请求，定位完从地址里去掉（replace，不多一条历史记录） | 登录 + 配对 |
| `/sessions` | 手机「会话」标签页：原来左侧抽屉里的内容铺满一屏（[§ 3.3](#33-手机-768px)）。宽屏上回到 `/inbox`（左栏就在那里） | 登录 + 配对 |
| `/more` | 手机「更多」标签页：节点（每台已配对节点的首页和设置）、设置、账号菜单。宽屏上回到 `/inbox` | 登录 + 配对 |
| `/setup` | 首次向导：安装 daemon → 配对 | 登录 |
| `/pair` | 输入短码配对新节点；支持配对链接 `/pair#code=<短码>`（短码在 URL fragment，不是 query） | 登录 |
| `/unlock` | 账号下、这个浏览器还没配对的节点列表（§ 4.3.1） | 登录 |
| `/unlock/:node` | 用扫码批准、接入码或节点口令解锁一台节点（§ 4.3.1） | 登录 |
| `/n/:node` | 节点首页：项目列表、临时会话、最近会话。首页换成「待处理」之后的入口：桌面左栏节点下拉里的「节点首页」，手机「更多 → 节点」；会话页和项目页的面包屑第一级也是它 | 登录 + 配对 |
| `/n/:node/p/:project` | 项目页：该项目的会话历史和管理（新建会话去 `/n/:node/new`） | 同上 |
| `/n/:node/s/:session` | 会话页（主界面）。`?seq=<事件 seq>`：搜索命中带来的，加载并定位到那条消息（§ 4.6、§ 9.1） | 同上 |
| `/n/:node/new` | 新建会话（空白页，不显示历史），`?project=&agent=`。左栏项目行的「＋」、项目页的「新会话」都到这里；独立路由也方便从通知和命令面板直达 | 同上 |
| `/n/:node/files/*` | 只读文件浏览（§ 4.7）。`*` 就是 `fs.list` / `fs.read` 的 `path`：`<项目名>/<相对路径>`（scratch 会话的工作目录是 `.scratch/<会话 id>/…`），每段做百分号编码；空（`/n/:node/files`）显示节点上的项目列表。选中的文件和目录都在 URL 里，可以分享 / 刷新 | 同上 |
| `/n/:node/settings` | 节点设置：agent、设备、接入、workspace、限制、关于。`?tab=<agent\|devices\|enroll\|workspace\|limits\|about>` 直达某个标签；推送和安全提醒点进来用 `?tab=enroll`，`enroll_requested` 另带 `review=1`，自动弹出待批准请求的对话框 | 同上 |
| `/settings` | 账号设置，子路由见 § 4.9 | 登录 |
| `/admin` | 管理：账号（搜索、授予 / 取消管理员、删除）、邀请（仅 `single`）、hub 状态 | 管理员 |

本账号的节点、只是这个浏览器还没配对 → 跳到 `/unlock/:node`（从通知、书签、另一台设备发来的链接进来时常见）；不是本账号的节点、已吊销的节点 → 404 页带「返回」；节点离线不是 404，正常进入页面并显示离线状态。这个浏览器配对过、但账号下已经没有的节点（在别的设备上被移除了，§ 4.8）→ 整页说明「这台节点已从账号移除」，带「忘记这个节点」和「配对另一个节点」。判断用左栏已经拉过的 `GET /api/devices`（已配对的节点不为此专门去问 hub）；列表的拉取时间早于这个节点的配对时间时不算（刚配对的节点可能还不在缓存的列表里），列表没拉到时也不算。只提示、不自动删。

## 3. 布局

### 3.1 桌面（≥ 1200px）

```
┌──────────┬──────────────────────────────────────┬────────────┐
│ 待处理  3 │ 面包屑  节点 / 项目 / 会话标题  状态   │ 会话信息    │
│ 节点过滤  │──────────────────────────────────────│            │
│ 新建项目  │                                      │ 工作目录   │
│ 搜索 ⌘K  │                                      │ Agent  2 个│
│          │           消息流                      │ 主 agent ● │
│ 项目 A ＋│                                      │ └子 agent ●│
│  · 会话1 │                                      │ └子 agent ✓│
│  · 会话2 │                                      │ 轮数 / 费用│
│ 项目 B ＋│  ╭────────────────────────────────╮  │────────────│
│ 临时会话  │  │ ＋ 输入框               ⏹  发送 │  │ 待审批 (1) │
│          │  ╰────────────────────────────────╯  │ 操作       │
│──────────│  [权限▾][更多]        [模型▾][思考▾] │            │
│ ● 在线   │                                      │            │
│ 账号 ▾   │                                      │            │
└──────────┴──────────────────────────────────────┴────────────┘
   260px 可取消固定       自适应                    320px 可收起
```

- 左栏：节点过滤器（顶部，下拉，多选：勾了哪些节点，左栏就显示这些节点上的所有项目；默认全部节点，至少留一个；勾选记在 localStorage；选单个节点时按钮上显示它的名字和在线状态点，多个时显示「全部节点」或「n / m 个节点」；账号下这个浏览器还没解锁的节点列在下拉底部，带锁图标，点了去 `/unlock/:node`；这个浏览器配对过、账号下已经没有的节点（§ 2）另列一组「已从账号移除」，点了去它的页面，在那里忘记它；下拉里还有「节点首页」和「节点设置」，指页面当前所在的那个节点；不在某个节点上的页面（比如「待处理」）指上次打开的节点）、新建项目（过滤器右边的图标按钮，原地打开和节点首页同一个新建项目对话框：空项目 / 克隆 / 已有目录；默认建在页面所在的节点，不在勾选里就用第一个勾选的，对话框顶上可以换节点，离线和不管理 workspace 的节点标「不可用」、选了不能提交）、搜索（再右边的图标按钮，打开命令面板，和 `⌘K` 是同一个，§ 9.1）、按项目分组的会话树（合并所有勾选的节点，最近活跃的项目在前；节点的项目列表拉到过时，列表里已经没有的项目（进了回收站、解除关联、目录被手工删掉）不成组，它的会话仍然能从节点首页、搜索和项目页打开；勾了多个节点时项目行上标出所属节点；每个项目默认展开最近 5 个会话，会话列表前不画竖线；项目行右边一个「＋」，在这个项目里新建会话——左栏没有单独的「新会话」按钮，新会话都从项目的「＋」、项目页或命令面板进入；没有任何项目和会话时，空状态里还有一个「新建项目」按钮，打开同一个对话框）、临时会话分组、底部连接状态和账号菜单。Logo 下面是导航区，目前一项「待处理」（[§ 4.11](#411-待处理-inbox)），右边是「现在」段的个数（没有就不显示数字），当前在这一页时标 `aria-current`；再下面才是节点过滤和会话树。等审批的会话、标了「待处理」而且已经停下来的会话（[§ 4.6.1](#461-待处理和未读)）不再有置顶组，它们和接入请求、出错的会话一起在「待处理」页里。会话树上面是「Recent」组（中文界面里叫「运行中」）：列出正在进行中的会话（`running` / `starting` / `queued`，和项目页「进行中」筛选同一个口径；归档的不列，等审批的会话在「待处理」页里，这里不重复列），按最近更新排，每行右边带所属项目名（临时会话没有），勾了多个节点时再带节点名；没有进行中的会话时整组不显示。会话在项目树里照常在，Recent 只是多一个入口。这一组可以在外观设置里关掉（默认开）。左栏可取消固定（Logo 旁的图钉按钮或 `⌘B`）：取消固定后只留一条 48px 的窄条（Logo、搜索、新建项目、「待处理」入口，底部是图钉按钮；入口上是「现在」段的一个个数，不再是待审批和待处理两个），鼠标在窄条上停一下，整个左栏就从窄条后面滑出、盖在页面上，指针离开窄条和左栏后收回；点左栏外面、按 Esc、在左栏里点了会话或打开了搜索也收回；从左栏里打开的菜单或对话框还开着时不收回。触屏没有悬停，点窄条空白处滑出。浮出的左栏里点图钉就固定回来、常驻占位。固定状态记在 localStorage。宽屏时拖动左栏右缘调整宽度（默认 260px，200–480px，最宽不超过半个窗口），双击右缘恢复默认，键盘聚焦后 ← / → 调整；宽度也记在 localStorage
- 中栏：会话。消息列表和输入框共用一栏：正文宽度随中栏自适应、最宽 72rem（1152px），两侧留白随中栏宽度加大（≤ 544px 时 16px，≥ 800px 时 40px，之间线性过渡），中栏再宽就居中。只有一行顶栏：面包屑可点，最后一级是会话标题、点击编辑；右侧依次是「聊天 / 改动」开关（带图标，「改动」后面是未提交文件数）、危险模式 chip、状态 chip（运行中 / 等待审批 / 空闲 / 已结束 / 节点离线）、节点状态、「ⓘ」
- 右栏：会话信息面板，可收起，收起状态记在 localStorage

### 3.2 平板（768–1199px）

两栏：左栏 + 中栏，右栏变成从右侧滑出的抽屉，由头部的「ⓘ」按钮打开。「待处理」页（[§ 4.11](#411-待处理-inbox)）没有右栏：列表占满中栏，选中一条时它的详情从右侧滑出、盖住列表的右半边，关掉回到列表。

### 3.3 手机（< 768px）

单栏。**底部标签栏取代左侧抽屉**成为主导航：

```
┌───────────────────────────┐
│ 待处理 / 会话 / 更多 的页面 │
│───────────────────────────│
│  待处理    会话    更多     │  底栏：44px 以上的触控区 + 安全区
│    3                      │
└───────────────────────────┘
```

- 三个标签：「待处理」（`/inbox`，带「现在」段的个数）、「会话」（`/sessions`）、「更多」（`/more`）。标签栏是 `<nav>`，当前标签 `aria-current="page"`（另有下划线，不只靠颜色），「待处理」的可访问名称带个数（「待处理，3 件在等」）。现在是 待处理 / 会话 / 更多 三个。最终的排列是 待处理 / 清单 / ＋ / 会话 / 更多（§ 14.2）：清单和正中的「＋」到时插在「待处理」和「会话」之间，在那之前界面上没有它们
- 「会话」：原来抽屉里的东西（节点过滤、新建项目、搜索、Recent、项目树、临时会话）铺满一屏。「更多」：节点（每台已配对节点的「首页」和「设置」，以及「配对节点」）、设置、最下面是账号菜单（退出、扫码批准新设备、管理——手机没有左栏了，它们要有入口）
- 会话页、节点首页、项目页、设置等所有其余页面都是全屏的二级页：进去时标签栏收起，顶栏左边是返回按钮（走浏览器历史，手势返回也是同一条路；没有上一页，比如从通知直接进来，就回「待处理」），返回时标签栏恢复。只有三个标签页的根页面显示标签栏
- 三个标签页一旦打开过就常驻在外壳里，切走只是藏起来（保留布局，`inert`），所以各自的滚动位置和没发出去的输入（比如提问卡片里填了一半的回答）切回来还在

- 会话页占满屏幕，头部只留返回、标题、状态 chip、「ⓘ」
- 输入区固定底部，`100dvh` + `env(safe-area-inset-bottom)`，iOS 键盘弹起时输入框跟随
- 选项（模型 / 思考 / 权限；新建会话还有项目、工作位置、agent）收进输入框里左侧一个「⚙」按钮，点开底部弹层
- 待审批请求在会话页里以底部横幅出现，不遮消息；在节点首页等页面上同样有一条横幅，「查看」直达那个会话。「待处理」页里每条请求在行内展开（[§ 4.11](#411-待处理-inbox)）
- 搜索：「会话」标签页里的搜索按钮（和桌面左栏的是同一个）打开同一个命令面板（§ 9.1）。面板贴近屏幕顶部，软键盘弹起时输入框和前几条结果不会被盖住；每条内容命中是标题一行（节点名、时间在同一行）加最多两行片段
- 文件浏览（§ 4.7）：树和预览是两屏。URL 指向文件时只显示预览（头部有返回，回到它所在的文件夹），否则只显示树；树的展开状态在切换时保留

### 3.4 状态横幅（全局）

在头部下方，按优先级只显示一条：

1. 和 hub 断开，正在重连（红）。hub 终止这条连接、不再自动重连时换成对应的横幅：被另一个实例顶掉、设备被吊销、协议版本不兼容，以及（`multi`）账号的在线连接数到上限（`auth_fail { quota }`，红，带「查看用量」→ `/settings/quota`）
2. 节点离线，消息会留在本地（黄）
3. 有设备请求接入某台节点（蓝，带「查看」，打开批准对话框，§ 4.3.2；请求结束就消失）
4. 有 N 条未发送消息（黄，带「现在重发」）
5. 该浏览器尚未启用通知（蓝，带「去开启」→ `/settings/notifications`，可关闭，只提示一次）。同时满足才显示：浏览器能收推送（§ 4.9 的能力检测）、hub 配了推送（`/api/config.push_available`）、这个浏览器配对过节点、本浏览器没有推送订阅、浏览器没有拒绝过通知、`/settings/notifications` 以外的页面（在那一页上不催）、用户没关过。点「去开启」也算提示过了；关闭（或点了「去开启」）记在 localStorage 的偏好 `notifyBannerDismissed` 里，之后不再显示。没有注册 service worker（开发服务器）时也不显示
6. 新版本 Web UI 已就绪，刷新生效（蓝）

## 4. 页面

### 4.1 登录 `/login`

- 从 `GET /api/config` 拿 `mode` 和启用的登录方式（`login_methods`），没启用的不显示
- 布局顺序：GitHub / Google 按钮 → 邮箱 → token（折叠在「使用 token」链接后，只在 `single`；只开了 token 时直接显示表单）。passkey 登录还没实现（[roadmap](../roadmap.md)），实现后排在最前面
- **GitHub / Google**（`login_methods` 里有 `github` / `google` 才显示）：按钮是整页导航（`<a href>`）到 hub 的 `/auth/oauth/<p>/start?next=<登录后回到的路径>`，不是 fetch，授权码流程在 hub 里走完（[hub.md § 2.2.1](hub.md#221-oauth-登录)）。回调只回得到 `public_url`：当前页面的 origin 不是 `config.public_url` 的 origin（局域网 http、IP 直连）时按钮显示但禁用，悬停和按钮下面一行字说明「只能在 `<public_url>` 上使用」
- **OAuth 失败**：hub 重定向回来带 `?oauth_error=<code>&provider=<p>`，在表单上方显示一条错误（每个码一句话，认不出的码给一句通用的）：`cancelled`、`provider_error`、`server_error`、`invalid_state`、`registration_closed`（「这个 hub 仅限受邀注册，而且没有账号对应这个 GitHub 账号。请向管理员要一个邀请链接」）、`invite_invalid` / `invite_expired` / `invite_used`、`identity_taken`、`already_linked`、`not_signed_in`
- 邮箱两步（`/api/config.login_methods` 里有 `email` 才显示。[ADR-37](../decisions.md#adr-37-web-push邮箱验证码登录和邮件通知)）：输入邮箱 → `POST /auth/email/send` → 输入 6 位码（`inputmode=numeric`、`autocomplete="one-time-code"`，输满自动提交）→ `POST /auth/email/verify`。按 hub 回的 `resend_after_secs`（缺省 60 秒）倒计时后才能重发；码不对显示「验证码不对或已过期」。文案按模式不同：
  - `single`：发码后显示「如果这个邮箱绑定了账号，验证码已经发出」（hub 不告诉你邮箱有没有绑定）；一句提示「邮箱要先在账号设置里绑定才能用来登录」
  - `multi`：页面副标题是「登录；还没有账号的话，登录时会自动为你创建一个」；提示「我们会给这个邮箱发一个 6 位验证码。如果这个邮箱还没有账号，输入验证码后会自动创建」；发码后显示「如果邮箱地址没错，6 位验证码已经发出……输入后即可登录；如果你是新用户，会同时创建账号」，按钮是「继续」（`multi` 里没有「先绑定」的说法，任何邮箱都能收到码）
- 邀请（仅 `single`；`multi` 忽略暂存的码）：`/invite/:code` 把 code 暂存在 sessionStorage，登录页读到就显示「接受邀请」卡片，点了用 `/auth/invite` 兑换；有 OAuth 时卡片下提示「也可以用下面的第三方账号来创建账号」，GitHub / Google 按钮的 URL 带上 `invite=<code>`，由 hub 在 OAuth 登录时兑换。没有邀请的 `single` hub 上，邮箱码只给已绑定邮箱的账号用，OAuth 新用户会得到 `registration_closed`
- **服务条款 / 隐私政策**：`/api/config` 带了 `terms_url` / `privacy_url`（hub 的 `ANYCON_TERMS_URL` / `ANYCON_PRIVACY_URL`）时，所有登录方式下面一行小字「继续即表示你同意服务条款，并已阅读隐私政策」，两个词各链接到对应地址（`target="_blank"`、`rel="noopener noreferrer"`）；只配了一个就只提那一个，都没配（自建 hub 的默认）就没有这一行。Web UI 里账号只在这一页创建（OAuth 从这里发起，邀请页也转到这里），所以只放这一处
- 删账号之后整页跳到 `/login` 时，显示一次「账号已删除」的提示（§ 4.9）
- passkey 使用 conditional UI（实现后）：页面加载即发起 `navigator.credentials.get({ mediation: 'conditional' })`，有 passkey 的用户点一下自动填充就进去

### 4.2 首次向导 `/setup`

账号下一台节点都没有时的落地页（账号下有节点、只是这个浏览器没配对时去 `/unlock`，§ 4.3.1）。三步，每步可跳过：

1. **装 daemon**：按检测到的平台给命令（macOS brew、Linux 安装脚本、Windows 的 PowerShell 安装脚本、「其他」），`anycon init --hub <当前 hub 地址>` 已填好 hub 地址，一键复制
2. **配对**：告诉用户在那台机器上跑 `anycon pair`，下面是短码输入框（同 `/pair`）
3. **完成**：配对成功后先问要不要给这台节点设口令（「出门在外、手边没有已配对设备时，用它在任何设备上解锁这台节点」，`node.set_enroll_password`，可跳过，之后在节点设置的「接入」里设），再问要不要给这个浏览器开通知（「开启通知」直接走 § 4.9 通知页同一套：权限提示 → 订阅 → 上报 hub；可跳过，之后在 设置 → 通知 里开。这个浏览器收不了推送、hub 没配推送、通知已被浏览器拒绝或已经开着时不问，直接往下；读状态期间只显示一行「正在检查…」，不闪一下问题），然后跳到 `/n/:node`

### 4.3 配对 `/pair`

- 输入框接受 **16 位或 8 位**短码（`anycon pair` 默认给 16 位，`--short` 给 8 位），自动大写、每 4 位插入连字符、忽略粘贴进来的连字符和空格；整条配对链接粘贴进来也认（取其中 `#code=` 后面的）。确认后先做一次 Argon2id 派生（浏览器里约 0.1–1 s，进度显示「正在派生密钥…」），再发 `pair_join`
- **配对链接** `https://<hub>/pair#code=<短码>`（二维码里就是它）：短码在 URL **fragment** 里，浏览器不会把它发给 hub，hub 和反代的日志里也没有。页面从 `location.hash` 读它，读完立刻把它从地址栏和历史记录里擦掉（短码只在内存里；旧的 `?code=` 形式还能读，同样擦掉）。登录态没有时先去登录：跳转前把短码放进 `sessionStorage`，**登录页的 URL（path / query / hash）和历史栈里都不能出现短码**——否则用户在登录页刷新一次，短码就进了 hub 和反代的访问日志；登录成功回到 `/pair` 时取出并立刻删除
- **从链接带进来的短码不会自动开始配对**：先显示一个确认步骤（「用这个短码配对这个浏览器？」+ 确认按钮），点了才开始。原因：攻击者可以拿一台全新的 daemon 生成链接发给已登录的人，自动开始会把攻击者的节点静默加进受害者的账号
- 进度：连接 hub → 派生密钥（Argon2id，约 0.1–1 s）→ 撮合 → 握手 → 与节点确认 → 完成。「与节点确认」就是等 daemon 经新建立的加密传输发来的 `pair.ack` 并校验（见 § 6.4），每步有超时提示
- **落盘时机**：节点只有在 `pair.ack` 校验通过之后才写进 IndexedDB 和 store。中途任何一步失败，都不留下半成品
- 失败分支：短码不存在或过期 / 频率限制 / 握手失败（PSK 不对，几乎只在手输错时发生，提示重试）/ 配额 / **确认失败**（30 秒内没收到 `pair.ack`，或 `pair.ack` 里的 id、指纹与 hub 告知的不一致：不保存任何东西，提示重试，并提醒核对 hub 地址是否可信）/ **公钥冲突**（本浏览器里已有同 id 的节点，但公钥不同：不覆盖，提示先「忘记这个节点」再配对）
- 设备名默认 `浏览器 · 系统 · origin 主机名`，完成前可改

### 4.3.1 解锁节点 `/unlock`

[ADR-36](../decisions.md#adr-36-账号内接入账号负责路由daemon-负责开门)，消息序列见 [protocol.md § 4.4](../protocol.md#44-账号内接入)。账号下有节点、只是这个浏览器还没和它配对时用（换了新手机、借来的电脑、清过浏览器数据），不需要短码。

**列表 `/unlock`**：`GET /api/devices` 里 `kind = daemon`、未吊销、本浏览器 IndexedDB 里没有的节点，每行：名称、平台、在线状态、最近在线。这些名称来自 hub、**未经认证**，只用来挑节点；解锁完成后以 `pair.ack` 里的名字为准。只有一台时直接进 `/unlock/:node`。底部「用短码配对」→ `/pair`。

**`/unlock/:node`**：标题「解锁 <节点名>」和一句说明「这个浏览器还没和这台节点配对。选一种方式证明是你：」。节点离线时所有入口禁用，说明「解锁需要节点在线」（在线状态来自 `/api/devices`，节点上线后自动恢复）。四个入口，同一时刻只进行一个：

| 入口 | 适合 | 流程 |
|---|---|---|
| **用已配对的设备扫码**（默认展开） | 手机在手边 | 点「显示二维码」才开始（打开页面不自动开始，免得忘在后台的标签页一直占着 daemon 的接入名额和 hub 的限速）：发 `enroll_begin` 和 `EnrollHello { method: scan }`，页面显示二维码（内容 `anycon-enroll:1:…`）和 5 分钟倒计时，下面一句「在手机上打开 anycon，点账号菜单里的「扫码批准新设备」」。二维码在收到 `reply { wait_approval }` 之后才出现，只在内存里，不写 IndexedDB、不进 URL。到期、和 hub 的连接断了、或者二维码正显示着时改了设备名，都自动换一个新的（连续换 12 次后停下，显示「重新开始」；页面在后台时到期不换）；还没人批准时标签页切到后台就取消这次接入（批准之后的握手让它走完），回到前台显示「重新显示二维码」，不自动重开。手机批准后自动往下走 |
| **在已配对设备上批准** | 手机在手边，但不方便扫码 | `EnrollHello { method: code, approval: true }`。页面显示「已经向你的已配对设备发了请求。在那台设备上点批准，然后在这里输入它显示的 6 位码」，下面是 6 位输入框（`inputmode=numeric`、`autocomplete="one-time-code"`，输满自动提交），剩余次数显示在输入框下面 |
| **我有接入码** | 已经在已配对设备的「添加设备」里，或用 `anycon pair --enroll` 拿到了码 | `EnrollHello { method: code, approval: false }`，同一个 6 位输入框 |
| **节点口令** | 手边没有任何已配对设备 | `EnrollHello { method: password }`。口令输入框（`type=password`），旁边一句「在借来的电脑上，不要让浏览器保存口令」；anycon 自己从不保存口令。提交后先显示「正在派生密钥…」（Argon2id，§ 6.5） |

- **进度**：连接 hub → 发起接入 →（等待批准）→ 验证 → 握手 → 与节点确认 → 完成。「与节点确认」就是 `pair.ack` 校验，规则、落盘时机、公钥冲突的处理和 `/pair` 完全一样（§ 4.3、§ 6.4）
- **连接**：这个浏览器在这个 origin 上还没有 device token 时，开一条升级请求带登录 cookie 的临时连接；已经是这个 hub 上的设备（配对过别的节点）时，在现有连接上发 `enroll_begin`。成功后按 `pair_done` 原地升级 / 加入节点，然后照常走 IK
- **设备名**：默认同 `/pair`，作为 `EnrollHello.hint` 发出去（让批准的人认得出来），完成前可改
- **失败分支**（`EnrollReply` 的 `rejected.reason` 和 `enroll_failed.reason`）：
  - `wrong_secret`：码 →「码不对」和剩余次数，用完显示「这个码已作废，重新请求」；口令 →「口令不对」
  - `backoff`：「尝试太多次了，<倒计时> 后再试」，期间提交按钮禁用
  - `locked`：「这台节点的口令解锁已被锁定（连续输错 10 次）。在节点本机运行 `anycon passwd --enable`，或在已配对设备的节点设置「接入」里重新启用」
  - `password_not_set`、`method_disabled`：「这台节点没有开启这种方式」，引导到其他入口；`no_code`：「这台节点现在没有有效的接入码，在已配对设备上重新生成」
  - `denied`：「请求被拒绝了」；`expired`、`timeout`：「超时了」+「重新开始」；发出 `enroll_begin` 后 20 秒没有任何回应（hub 的限速回执可能被每秒一条的预算丢掉）：「没有收到 hub 的回应，可能是请求太频繁，稍后再试」，只能手动「重新开始」，扫码入口也不会自己重试（接入码入口的 `expired` 说「码已过期或次数用完」）
  - `offline`、`busy`（「这台节点同时有太多接入在进行」）、`rate_limited`、`quota`：各一句说明
  - `not_found`（不是本账号的节点）：404 页
- 离开页面、切换入口时发 `enroll_cancel`

### 4.3.2 批准接入、应用内扫码

在**已配对**的浏览器上，处理别的设备发来的接入请求（ADR-36）。

**批准对话框**（新设备选了「在已配对设备上批准」）：收到 `node.enroll_requested` 时出现 § 3.4 的横幅，点「查看」打开：

```
有一台设备想接入 mac-mini
  Chrome · Windows（设备自报，未经验证）· 2 分钟前 · 还剩 3:12

只批准你眼前这台设备。
如果不是你刚刚在另一台设备上发起的，点「拒绝」。
                                         [拒绝]  [批准]
```

- **批准** → `node.enroll_approve { enroll_id }` → 对话框换成大号的 6 位码和倒计时，下面一句「在新设备上输入这个码。不要告诉任何人，anycon 不会向你索要它。」码只在这个对话框的组件状态里（不进 store、不进 IndexedDB），关掉就看不到了；新设备用掉或过期后对话框显示「已完成」/「已过期」
- **拒绝** → `node.enroll_deny { enroll_id }`
- 别的设备先处理了（`node.enroll_resolved`，或自己答复时得到 `already_resolved`）→ 收起成一行「已由 iPhone 批准 / 拒绝」
- hint 显示前清掉控制字符和双向控制符，按字符截到 64；没有就显示「未知设备」
- 打开页面或重连后用 `node.enroll_list` 补齐还在等的请求
- 节点设置「接入」标签的待批准列表里，`scan` 请求只能拒绝或去扫码（批准要扫到二维码里的密钥）

**应用内扫码**（新设备选了「用已配对的设备扫码」）：入口在账号菜单的「扫码批准新设备」和节点设置的「设备」标签。没有摄像头（`navigator.mediaDevices` 不可用或枚举不到视频输入）时不显示入口。

- 全屏对话框，`getUserMedia({ video: { facingMode: "environment" } })`。画面只在本地解码，不上传、不录制、不截图。优先用 `BarcodeDetector`，浏览器没有时用打包进来的 JS / wasm 解码器（CSP 只允许同源脚本，不能从 CDN 拉）
- 只认 `anycon-enroll:1:` 开头的内容，其他内容提示「这不是 anycon 的接入二维码」；二维码里的节点不是这个浏览器配对过的 →「这个浏览器没有和 <节点> 配对，不能批准」
- 认出来后立刻停掉摄像头。`node.enroll_list` 里这个请求不是 `scan` →「这个二维码对应的不是扫码请求」；是 `scan` 但不在等批准 →「这个请求现在不在等批准」。两种都清掉扫到的密钥，不进确认页。否则显示确认页：节点名、`node.enroll_list` 里这个请求的 hint（标「未经验证」）、一句「只在这个二维码就显示在你眼前那台设备上时批准」，按钮「批准」「取消」。确认后 `node.enroll_approve { enroll_id, secret }`，成功显示「已批准，新设备会自动完成接入」
- 摄像头权限被拒：说明怎么在浏览器设置里打开，或者让新设备改用「在已配对设备上批准」
- 扫到的密钥只在内存里，确认页关掉就丢弃

**安全提醒**：收到 `node.security_event` 时弹 toast，例如「新设备 X 已接入 mac-mini」「mac-mini 的节点口令连续输错 3 次」「mac-mini 的口令解锁已被锁定」「mac-mini 的节点口令已被 iPhone 修改」，点开去节点设置的「接入」标签。

### 4.4 节点首页 `/n/:node`

- 头部：节点名、在线状态、版本、「设置」
- **项目**：卡片或列表（可切换），每个显示名称、git 分支、是否有未提交改动、最近修改、进行中会话数。点击进项目页。右上「新建」→ 对话框三种方式：空项目（名称、是否 `git init`）/ 从 Git 克隆（URL、名称可选，进度条走 `job.progress`）——节点有多个 workspace 根（`node.info.workspace_roots` 多于一项，[ADR-45](../decisions.md#adr-45-多个-workspace-根)）时，这两种方式多一个「位置」下拉（`project-new-root`），列出所有根，默认主根（标「默认」），`available = false` 的根灰掉并标「不可用」、不能选；选了主根（或没动）时 `workspace.create` / `clone` 不带 `root`，选了别的根才带；默认的根自己不可用时不能提交、给出原因；换节点或重新打开对话框时回到主根；只有一个根的节点和老 daemon（没有 `workspace_roots`）不显示这个下拉 / **已有目录**（`workspace.browse` 驱动的目录选择器：面包屑 + 子目录列表，带 git 标记，已是项目的灰掉并标出项目名；`blocked` 非空的不能选，显示原因（`hidden` / `workspace` 的能进入；拒绝表和数据目录点进去会被 daemon 拒绝，显示行内错误）：隐藏目录（在 `workspace.link_roots` 里显式列出才能关联）/ 系统或凭证目录，或者包含它们 / 在 workspace 里面或包含它 / anycon 数据目录 / 文件系统根；也可以直接粘贴路径；名称默认取目录名，可改；提交 `workspace.link`）。关联项目的卡片标「已关联」并显示路径；菜单里是「从列表移除」（`workspace.unlink`，说明不会删除文件）而不是「移到回收站」；`missing` 的显示「目录不存在」，不能新建会话，只能移除。`workspace.browse` 返回 `forbidden`（`link_roots` 为空）时这一项显示为不可用并说明原因
- **临时会话**：scratch 会话列表，每条有「转为项目」
- **最近会话**：跨项目按时间倒序，带状态 chip
- 离线状态：项目列表显示上次缓存，灰化，顶部黄条；新建按钮禁用

### 4.5 项目页 `/n/:node/p/:project`

- 头部：项目名（可改名）、分支、路径、「…」菜单（重命名、移到回收站）
- 关联项目（`kind = linked`）：头部多一个「已关联」徽标；菜单里是「从列表移除」（`workspace.unlink`）**替代**「移到回收站」，确认框写明目录和文件不会被删除、已有会话保留——同一个目录重新关联回来就能继续，这个名字以后指向别的目录时旧会话不能继续；`busy`（还有运行中的会话）时留在确认框里显示原因、可以重试
- `missing`（关联目录不在了）：显示说明卡（带「从列表移除」），**不渲染新建会话的输入框**，菜单里只剩「从列表移除」；新建会话页的项目下拉里它是禁用的。节点首页上 missing 的卡片灰化、不显示修改时间，要进项目页才能移除
- 会话列表：筛选 全部 / 进行中 / 等待审批 / 待处理（后面带个数，归档的不算）/ 已归档；每条显示标题、agent 图标、模型、最后一条消息摘要、时间，标了「待处理」的带一个 chip，停下来之后有未读的标题加粗并带红点，最右边是「待处理」开关（§ 4.6.1）；有 worktree 的会话再显示分支名（`⑂ anycon/x`）。左栏会话树里分支名放在悬停提示里
- 头部有「文件」按钮（`project-files`，`missing` 时不显示），到 `/n/:node/files/<项目名>`（§ 4.7）
- 头部有「新会话」按钮（`project-new-session`，`missing` 时不显示），到 `/n/:node/new?project=<名字>`；项目页本身不再放输入框，只是会话历史和管理
- **新建会话页** `/n/:node/new`：空白页，中间一行标题（「想在 X 里做什么？」）和输入框，不显示任何历史（历史在左栏和项目页）。输入框和会话页的 composer 同一个组件；宽屏时输入框顶上贴一条上下文栏（`composer-context`，比输入框略窄、垫在它后面），放项目（下拉，含「临时会话」，`missing` 的项目禁用；末尾是「新建项目…」，打开新建项目对话框，节点固定为当前节点，建好之后回到新建会话页并选中这个项目，节点离线时禁用，节点不管理 workspace 时不显示）和工作位置；下面的选项行左边是权限模式，右边是 agent（多于一个时）、模型、思考等级。发送后创建会话并跳转
- **工作位置**（新建会话页，ADR-34）：节点 `capabilities.worktree` 且项目是 git 仓库时，上下文栏里项目后面多一个按钮（`new-session-workspace-button`，「⑂ 新 worktree · main ▾」/「📁 当前目录 ▾」），点开是一个浮层（手机上直接在「⚙」底部弹层里）：
  ```
  工作位置 [ 新 worktree ][ 当前目录 ]
  基于     [main ▾]
  分支     [anycon/自动 ✎]
  ```
  - 分段控件（`Segmented fill`），`data-testid="new-session-workspace"`；选「新 worktree」时出现 base 下拉（`workspace.branches`：本地和远端两组，默认 `default_base`）和可选的分支名输入框（占位符 `<branch_prefix>/自动`，留空由 daemon 生成；输入时按 git 的分支名规则做基本校验）
  - 项目 `git_pending = true`（daemon 冷启动时 git 元数据还在算）：按钮的位置显示占位「正在读取 git 信息…」（`new-session-workspace-pending`），**一直到**收到 `workspace.changed { updated }`、重新拉到的项目不再 `git_pending` 为止；占位期间发送被挡住（按钮禁用并说明，回车也不发），不会悄悄按「当前目录」建会话。项目既没有 `git` 也没有 `git_pending`（旧 daemon）时，补拉一次 `workspace.list`（同一 `(节点, 项目)` 5 秒节流，请求超时 10 秒）期间同样占位，补拉回来仍没有就按非 git 项目处理。节点离线、节点不支持 worktree、临时会话、项目已有 `git` 时不占位
  - 初始选择：这个浏览器在这个 `(节点, 项目)` 上次的选择（localStorage，随 `lastUsed` 一起持久化），没有就用 `node.info.worktree.default_mode`
  - 项目是 git 仓库但 `worktree_ready = false`：按钮显示「当前目录」，浮层里的分段控件禁用并说明「项目目录不是仓库根目录，或者还没有提交」；非 git 项目、scratch 会话不显示这个按钮
  - 发送：这一行出现且可用时明确带 `workspace`（选「当前目录」就带 `{ mode: "local" }`），禁用 / 不显示时不带；`worktree_ready` 缺省（旧 daemon）按不可用处理。`session.create { …, workspace: { mode: "worktree", base, branch? } }`；创建后会话页头部先显示「正在创建 worktree…」，`git { action: worktree_created }` 之后变成分支 chip

### 4.6 会话页 `/n/:node/s/:session`

主界面。分三块：消息流、输入区、信息面板。

#### 消息流

事件 → 渲染的对应关系：

| 事件 | 渲染 |
|---|---|
| 用户消息 | 右对齐的浅灰底气泡；未发送的加「未发送」角标和重试 / 编辑 / 删除；附件显示在气泡上方：四种图片是缩略图（按 `width` / `height` 先占位，进入视口才用 `blob.get` 拉，点开看大图），拉不到显示「图片不可用」；其它文件是文件条（名字、大小、下载图标），点了才下载（见下面「附件」） |
| `turn_start` | 一条细分隔线，hover 显示 turn 编号和时间 |
| `thinking_delta` | 「思考中…」一行灰字（不画卡片），流式时显示最近两行，结束后折叠成一行「思考了 12 秒」。可展开。设置里可改为始终展开或隐藏 |
| `text_delta` | Markdown 流式渲染（react-markdown + shiki），代码块有复制按钮和语言标签。**远程图片（`http(s)://`）不会自动加载**：被提示注入的 agent 可以借图片 URL 把数据带出去，所以只显示成带主机名的占位按钮，点了才请求；hub 的 CSP（`img-src 'self' data: blob:`）本来就不允许页面加载第三方图片，点了之后会退成一条链接「从 <主机> 打开」。`data:image/*`（非 SVG）、`blob:` 直接渲染；同源只放行已知静态资源路径（`/assets/<名字>`、`/icons/<名字>` 和几个固定的根文件：只有一层路径，名字限 `[A-Za-z0-9._-]`、≤ 128 字符，不能带 `?`、百分号编码或 userinfo），其他同源路径（比如 `/x?d=…`，能不点击就把内容送到 hub）同样走占位按钮。`javascript:` 等协议的链接被拦；**不开 `skipHtml`**——没有 rehype-raw，react-markdown 默认就把 HTML 当文本转义（开了会把 `Vec<String>` 里的 `<String>` 当标签吞掉） |
| `tool_call` 按 `category` | 收起时是一行灰字（图标 + 摘要 + ›，失败的是红字，不画卡片），展开的内容放在下面的框里；连着的思考 / 工具行之间只留很小的间距。`shell`：终端样式块，命令 + 输出，**默认收起**：一行摘要，agent 给了命令说明（Claude Code Bash 的 `input.description`）就显示说明，否则显示 `$ 命令`，放不下截断、悬停看全文；展开后先是折行显示的完整命令（右上角复制按钮，复制不带 `$ `），再是输出，输出超过 20 行再折叠；`file_edit`：文件路径 + diff 视图（react-diff-view），默认折叠显示 +N −M；`file_read` / `search`：一行摘要（「读取 src/a.ts」「搜索 "foo" → 3 个结果」），可展开；`web`：URL 一行；`mcp` / `other`：工具名 + 可展开的 JSON；`shell` 的后台命令（`tool_result.detail.background`）在补上最终结果之前写「后台运行中」并转圈；`subagent`：一行标题（子 agent 的说明、它一共调了几次工具、运行中 / 后台运行中 / 失败），带 `parent_id` 指向它的调用都收在这个块里、不在主流里单独成行（几个子 agent 并行时各自一块，不再交错），展开后缩进一级按顺序列出、最后是子 agent 的结果（Markdown）；收起且还在跑时下面露出它最近的一次调用。父调用不在已加载的历史里时子调用照常平铺 |
| `tool_output_delta` | 追加进对应 `shell` 块，边跑边显示 |
| `tool_result` | 合并进对应 `tool_call` 块，`is_error` 时块变红 |
| `plan` | 一张可折叠的待办卡片，随后续 `plan` 事件在**同一 turn 内**原地更新，不新增卡片；下一个 turn 另起一张（跨 turn 的话那张卡离当前太远） |
| `permission` (`kind = tool`) | 内嵌卡片：工具类别图标、摘要（命令全文 / 文件路径 / diff）、详情可展开、按钮**按 `options[]` 渲染**（常见是「允许」「本会话都允许」「拒绝」，按 `kind` 着色），`reject_*` 可附一句话。答复过的收成一行灰字「标题 — 已由 iPhone 允许（选项）›」，点开看命令 / diff；`by_device = "daemon"` 显示「已被 anycon 自动允许 / 拒绝 / 处理」（超时、取消、项目目录变了都会这样）；自己答复时得到 `not_found` 且 `data.reason = "project_dir_changed"`，卡片定格成一行说明「项目目录变了，这个请求已被拒绝，turn 已中止」，不再给按钮；其它 `not_found` 显示通用的「这个请求已经不存在」 |
| `permission` (`kind = plan`) | 计划卡片：渲染 `detail.text` 的 Markdown，按钮「开始实施」「继续规划」（可附修改意见）；按钮完全由 `options[]` 渲染，v0.1 没有「开始实施，回到之前的模式」 |
| `permission` (`kind = question`) | 问答卡片：每个问题一组单选 / 多选 / 文本框，一次提交全部 `answers`；每题都答完才能提交，`optional` 的题（MCP elicitation 表单里非必填的属性）标「可选」、可以留空，已选的单选可以清除，留空的不出现在 `answers` 里。答复过的留在对话里：一行灰字「标题 — 已由 iPhone 回答 / 跳过」，下面按题列出问题和回答（`permission_resolved.answers`：选项 id 换成显示名，多选用逗号连接，自由输入原样，没答的写「未回答」）；答复附的话（`permission_resolved.message`，跳过的说明、拒绝的理由，所有 kind 都是）跟在下面。没记回答的旧事件只有那一行 |
| `permission` (`kind = other`) | 确认卡片：`detail.text` 作说明，按钮按 `options[]` 渲染。带 `detail.url`（MCP server 的 URL 模式授权）时显示**完整的 URL**（不截断、不省略主机名之后的部分）和一个「打开」按钮：只认 `http` / `https`，其它协议不给打开入口（只显示成文字）；链接用 `target="_blank" rel="noopener noreferrer"` 在新标签页打开。打开本身不答复请求：用户在那个页面完成后回来点「我已完成」（`allow_once`）或「拒绝」 |
| `turn_done` | 一行：「复制」图标（复制这一轮 agent 的全部文字，Markdown，不含工具输出）+ 灰字：模型、用时、token 数、费用（agent 报了才显示） |
| `error` | 红色块，`recoverable` 时带「重试」。块里依次是 `message`（agent 的原文）、认识的 `code` 的本地化说明（`usage_limit` / `rate_limited` / `overloaded` / `budget_exceeded` 各有一句。`rate_limited` 的说明保持中性（频率或用量限制）：旧 daemon 上 Codex 的用量耗尽等也还是这个码；`usage_limit` 有 `resets_at_ms` 时说本地化的恢复时间，没有时说「用量或额度已达上限，查看套餐 / 计费或等窗口恢复」，不承诺会恢复，因为 API key 的计费额度用完不会自己恢复）、`code` 本身。其它带 `resets_at_ms` 的 `code` 多一行本地化的恢复时间（当天只写时间，其它日子带日期，同 `notice` 的 `rate_limit`）；`usage_limit` 且 `limit_scope = model` 时再加一句提示换模型（输入区已有模型选择，不加新控件）；`overloaded` 的说明里也提到可以换模型。不认识的 `code` 只显示 `message` 和 `code`，没有说明。上游没有给恢复时间 / 范围就不显示，不估算 |
| `status` | 不单独渲染，驱动头部 chip 和 composer 状态 |
| `file_changed` | 不单独渲染（改了哪些文件看「改动」视图）；git 会话里触发一次 git 状态刷新（见下） |
| `settings_changed` | 一行灰字：「模型已切换为 …」 |
| `git` | 一行灰字（失败是红字，冲突 / worktree 被保留是黄字），按 `action`：「已在 worktree `anycon/x` 中开始（基于 main，复制了 2 个文件）」「worktree 创建失败：…」「已删除 worktree（分支保留 / 分支已删除）」「worktree 有未提交的改动，已保留」「已按分支重建 worktree」「worktree 目录不见了」「main 没有新提交」「已合并 main 的 3 个提交」「合并 main 时 2 个文件有冲突：a.rs、b.rs」+ 按钮「让 agent 解决」「放弃合并」「已放弃合并」。同时触发 git 状态刷新 |
| `task` | 后台任务的进度（workflow、后台子 agent、后台命令）。每条是整条快照，按 `id` 只留最新一条。有 `tool_id` 且对应的 `tool_call` 块在已加载的历史里时，进度挂在那个工具块上显示（工具行本身的状态跟着任务走：挂着的任务有一个在 `running`，工具行就是「后台运行」并一直转圈——Claude Code 的 `Workflow` 和 Codex 的 `spawnAgent` 调用立刻就返回结果、不带 `detail.background`，所以不能只看结果；任务都结束了，有 `failed` 的算失败，否则算完成；任务可能从 `completed` 回到 `running`（Codex 的子 agent 收到了新输入），工具行和进度跟着变回去）；对不上就在第一次出现的位置单独成一个块，之后的快照原地更新。`workflow`：按 `phases` 分组，每个 agent 一行（状态图标、`label`、token 数、最近调用的工具，失败的显示 `error`，重试过的标第几次，来自缓存的标「缓存」），标题行是名字、状态、用量（token / 工具调用 / 用时）和 `summary`。`subagent` / `shell` / `other`：一行标题 + 状态、token、最近调用的工具、`summary`。终态的快照（完成 / 失败 / 已取消）定格；会话没有在跑（`status` 不是 `running` / `starting` / `waiting_permission`）且 `background_tasks == 0` 时，非终态的快照显示成「已停止」（daemon 重启或被强杀后历史里可能留着没收尾的快照） |
| `notice` | 消息流里的一行系统提示，不是错误（不画红块，没有「重试」）：`info` 灰字，`warning` 黄字。认识的 `code` 用界面语言的文案（`model_fallback` 写「模型已从 A 换成 B」，`rate_limit` 带恢复时间…），`message` 原文作补充（可展开）；不认识的 `code` 按 `level` 直接显示 `message`。`command_output`（`/context`、`/cost` 等本地命令的输出）用等宽字体的块显示 `message`，可折叠 |
| `message_delivery` | 不画新的块：把「可能没有送达」标在 `message_id` 对应的用户消息上（气泡改成虚线警示底色，下面一行警示 chip「可能没有送达」）。离线、会话已归档以外，chip 旁边有「重发」：用**新的** `message_id` 把同样的文字和附件引用再发一次（`session.send`；附件已经绑定在这个会话里，同一个会话内可以复用，不需要重新上传）。点过之后原消息固定显示「已重发」：发送被拒或没发出去时，新消息自己有「失败 / 未发送」气泡和它的「重试」，原消息上不再给第二个入口（两边都点会发两遍）。不自动重发，因为消息可能已经被 agent 读到。对应的用户消息不在已加载的窗口里就忽略；`state` 不认识的取值当作没有标记。历史回放时标记还在（事件在日志里） |
| `activity` | 视图级的临时状态，不进消息流的持久内容：turn 进行中显示在消息流最底部一行（`retrying`：「正在重试（2/10），5 秒后…」，带 `reason`；`compacting`：「正在压缩上下文…」），带转圈。收到任何内容事件（`text_delta`、`thinking_delta`、`tool_call`、`tool_result`…）、`turn_done` 或 `activity { state: none }` 时清掉；翻看历史时只有最后一个 `activity` 之后没有内容事件、而且会话还在跑（`status` 是 `running` / `starting` / `waiting_permission`）的才显示 |

- 列表虚拟化；初次进入拉最近 200 个事件，向上滚动再拉更早的（`session.history`）
- 自动跟随底部；用户向上滚动后停止跟随，出现一个圆形「↓」浮标（只有图标，「新消息」在 aria-label / 悬停提示里）
- 每条 assistant 消息 hover 出现「复制 Markdown」
- **从搜索命中进来**（`?seq=<seq>`，§ 9.1）：会话第一次同步完之后，先把历史往前补到那个 seq 前约 20 个事件（已经加载到就不发请求），切回「聊天」视图，把 seq 所在的那条消息滚到中间并用底色高亮约 2 秒（系统要求减弱动画时不淡出，到时间直接撤掉），之后不再自动跟随底部（来了新消息显示「↓」浮标）；然后把 `?seq=` 从地址里去掉（replace，不多一条历史记录），刷新或重新渲染不会再滚一遍。`seq` 是被索引那段文字开始处的事件（用户消息的 seq，或一段 assistant 文字第一个 `text_delta` 的 seq；长文字每 32 KiB 切一段索引），可以落在一个渲染块的中间，所以定位到「起点不晚于 seq 的最后一个块」。**加载的办法和限制**：`session.history` 只能从某个 seq 往前（`before_seq`）或往后（`after_seq`）翻，不能只取目标附近的一段——那样它和最新的事件之间缺一块、实时事件接不上——所以要把目标到已加载的最早事件之间的历史全部拉下来：一页最多 1000 个事件（还受 daemon 每页 192 KiB 的限制），拉完一次性并入（不是一页一页地重建视图），期间消息流盖一层「正在加载这条消息…」。最多翻 40 页：目标比这还靠前就停在翻到的地方，提示「太靠前，向上滚动继续加载」，会话照常打开；中途失败（节点离线、超时）已经拉到的照样并入，提示错误，会话照常打开

#### 输入区（composer）

- 一个圆角框：上面是待发送附件（图片是缩略图，其它文件是文件条），下面一行是「＋」、输入框、停止 / 发送；框下面一行是选项（宽屏）
- 「＋」点开浮动菜单，目前只有「添加文件或照片」（见下面「附件」），以后的入口都加在这里
- 自动增高的 textarea，最多 10 行后内部滚动
- `Enter` 发送、`Shift+Enter` 换行（手机上 Enter 换行，发送靠按钮；设置里可改）
- 运行中：发送按钮变「停止」（`session.cancel`）；此时输入的内容会**排队**成下一条消息，并明确标注「将在本轮结束后发送」。agent 支持 turn 中插话的（capabilities.`interject`）则直接发
- 后台任务：输入框附近有任务在运行时（`SessionSummary.background_tasks > 0`，或已加载的历史里有非终态且会话还在跑的 `task`）显示一个「N 个后台任务在运行」的 chip（主 turn 在跑还是已经空闲都显示），点开列出这些任务（名字、状态、用量；摘要也带上）。N 取 `background_tasks` 和历史里认出来的在跑的任务数中较大的一个，认出来的不够数时（事件不在已加载的历史里、旧 daemon 不报）多出来的写成「另外 N 个后台任务」。会话已经空闲（主 turn 结束了）时，弹层底部说明「它们结束后 agent 会继续处理」。没有在跑的任务时不显示
- 节点离线：输入框可用，发送后标「未发送」
- 归档：会话在运行或等审批时「归档」按钮禁用并说明「先停止或答复」（daemon 此时返回 `busy`）
- 已归档的会话：输入区（连同选项栏）换成一条「已归档 · 取消归档后才能发送消息」+「取消归档」按钮（`session-archived-bar` / `session-unarchive`），点了调 `session.unarchive`，成功后输入框回来；取消归档失败（`git_failed`）时说明「没能恢复会话的 worktree，会话仍是归档状态」。`send` 被 `invalid` / `archived` 拒绝时（别的设备刚归档），失败气泡和 toast 显示同一句说明，本地立刻把会话标成已归档，消息留着不丢；已归档会话的错误块不给「重试这一轮」
- 附件（ADR-35、ADR-44，见下面「附件」）：「＋」菜单选文件、粘贴、拖进输入区。节点 `capabilities.blobs` 为真，并且节点带 `capabilities.file_attachments`（任何 agent 都行，agent 不原生收的附件由 daemon 落到会话的工作目录）或者 agent 点名了至少一种图片，才显示；旧 daemon（没有 `file_attachments`）上保持只收图片
- 选项行（输入框下面）：左边权限模式和「更多」（其余 agent 特定选项），右边模型和思考等级，都是下拉（§ 5）；窄屏收进「⚙」底部弹层

#### 附件（ADR-35、ADR-44）

- **入口**：输入框左边「＋」（`composer-plus`）菜单里的「添加文件或照片」（`composer-attach`，可多选；节点带 `file_attachments` 时文件选择框不设 `accept`，否则 `accept` 是 agent 收的图片类型加 `image/*`）、在输入框里粘贴、把文件拖进输入区（拖入时整块高亮，提示「拖到这里添加文件」或「拖到这里添加图片」）。节点只收图片（旧 daemon）时，非图片文件给一句提示（「这个节点只接受图片」）后忽略；节点只收图片、而 agent 又没有可用的图片格式时没有「＋」；节点不在线时菜单项禁用并说明原因
- **图片还是文件**：`File.type` 是 `image/*` 或为空、且 agent 点名了（原生收）图片类型的，走下面的「规整」；规整失败（不是图片、解不开、编不出 agent 收的格式）而节点带 `file_attachments` 时，退回按文件原样上传，不提示（还是太大的照旧提示并忽略）。其它文件（以及 agent 不原生收图时的图片）在节点带 `file_attachments` 时一个字节不动地上传：mime 取 `File.type` 转小写、去掉参数，不合 daemon 的格式（protocol.md § 5.6）就用 `application/octet-stream`；声明成四种图片之一而文件头对不上的，改用文件头认出的类型，认不出就是 `application/octet-stream`（否则 daemon 会以 `mime_mismatch` 拒绝）。文件不解码、不做预览
- **规整**：上传前在浏览器里处理（ADR-35「2026-10 修订」）——长边 > 2 000 px 的一律缩到 2 000；缩完（或原图）> 1.5 MiB 就有损重编码（agent 收 WebP 且浏览器编得出 → WebP 0.9，否则 JPEG 0.9，有透明通道的先铺白底）；单张硬上限 3.75 MiB；带 EXIF 的 JPEG 一律重编码（方向转正、去掉 GPS 等元数据）；浏览器能解码而 agent 不收的格式（HEIC、BMP…）转成 agent 收的格式。agent 收的格式、长边 ≤ 2 000、≤ 1.5 MiB、没有 EXIF 的原样上传（动图 GIF 保持动图）。解不开的图给提示。文件名去掉控制字符和双向控制符；下载时文件名用 `<主名>.<mime 对应扩展名>`
- **大小和个数的上限**（上传之前先查，超了提示后忽略）：原样上传的文件，单个超过节点报的上限（`node.info.attachment_limits.max_bytes`，旧 daemon 没有就按默认的 10 MiB）的，在读内容、算哈希之前就按 `File.size` 拒绝，提示「单个文件最多 10 MiB」。一条消息最多 10 个附件；走规整的图片合计 ≤ 15 MiB（Claude 单次请求的体积限制，原样上传的文件不进请求、不占这个额度）；所有附件合计 ≤ 节点的单条消息上限（`attachment_limits.max_message_bytes`，缺省 20 MiB，daemon 另有同样的兜底）。再加的提示后忽略（文件在读内容之前就按 `File.size` 判断）。
- **上传**：选中就开始传（`blob.put_begin` → 每块 512 KiB 的 `blob.put_chunk` → `blob.put_end`；同一节点同时只有 1 张在上传、2 块在途，其余排队（规整可以提前做最多 2 张）——同一设备到 daemon 是一条有序的传输，这样「允许」「停止」最多排在约 1.4 MB 后面；daemon 每台设备同时也只收 8 个进行中的上传），输入框里一排附件（`composer-attachment`，`data-state` = `uploading` / `ready` / `error`，`data-kind` = `image` / `file`）：图片是 64 px 缩略图，点开看大图（和消息里的图同一个对话框）；文件是带图标、名字和大小的文件条，点了没有动作。上传中显示进度，失败的可以点重试（超过节点的 `sessions.max_attachment_bytes` 时显示「文件超过了这个节点允许的大小」），每个右上角有移除（移除时 `blob.discard`）。一条消息最多 10 个。有附件在上传时发送按钮禁用；上传完了，只有附件没有文字也能发
- **发送**：`session.send` / `session.create` 带 `attachments`；「未发送」的消息连同附件引用一起留在本地，重发照常（daemon 已回收的附件会得到 `not_found` / `blob`，「编辑」时从本地缓存重传）。新建会话失败后重发沿用第一次的 `message_id`（超时但其实建好了时 daemon 返回那个会话）。草稿里的附件引用随草稿持久化，刷新后用 `blob.get { max_bytes: 1 }` 探一下，已被回收的从缓存重传（缓存没有就提示并去掉）。节点带 `file_attachments` 时换 agent 不影响已添加的附件（agent 不原生收的由 daemon 落到工作目录）；旧 daemon 上换到不收某些附件的 agent 时，那些附件留在输入区、变暗（`data-unsupported`），发送时不带；新建表单里会提示（全都不收 / 有一部分不收各一句）。agent 不原生收的附件，daemon 在开 turn 时复制到会话工作目录的 `.anycon/attachments/<会话 id>/` 并把路径写进发给 agent 的文字，消息流里仍是用户发的原文；复制失败这一轮以 `attachment_failed` 错误结束（消息仍在历史里，处理好原因后重发），见 [daemon.md § 7.10](daemon.md#710-附件adr-35adr-44)
- **文件的显示和下载**：四种图片之外的附件（包括 `image/svg+xml`、`text/html`）**永远不内联显示**：消息里是文件条（按钮，无障碍名「下载 <名字>」），滚动时不拉，点了才按「缓存 → `blob.get` 分段拉 → 写缓存」取到内容，用 `application/octet-stream` 的 `Blob` 加 `<a download>` 保存（文件名是记录的名字去掉不安全的字符），下载中显示转圈，失败显示「下载失败，点击重试」。`useBlobUrl` 对非图片的 mime 一律不建 `blob:` URL——附件里的 HTML / SVG 没有机会在 Web UI 的源里渲染或执行
- **显示**：自己刚传的图直接用本地数据（同时写进 IndexedDB 的 `blobs` 缓存，键是 `blob_id`）；历史里的图先查缓存，没有再懒加载（`blob.get` 分段拉、同一节点同时最多 2 张），拉完写缓存，用 `blob:` URL 显示（CSP 已允许 `img-src blob:`）。点开是一个对话框看大图，带文件名、尺寸和下载
- 导出 Markdown 时图片写成 `[图片：<文件名>]`（en：`[image: <name>]`），其它附件写成 `[文件：<文件名>]`（en：`[file: <name>]`）

#### 分支 chip（ADR-34）

有 worktree 的会话在输入框上方靠右显示（宽屏上，「将在本轮结束后发送」的排队提示和它在同一行、靠左） `⑂ anycon/fix-login ← main  ↑3 ↓1  · 5 个未提交`（`data-testid="session-branch"`；没有的部分不显示）。数据来自 `SessionSummary.worktree` 和 `session.git_status`：进入会话页、`turn_done`、`file_changed`（防抖 2 秒）、`git` 事件、手动刷新时拉一次，不轮询。`state = creating` 显示转圈和「正在创建 worktree…」，`missing` 显示警告色「worktree 不见了」，`kept` / `removed`（已归档）显示中性色。点击切到主区的「改动」视图（见下）。不放在输入框下面的选项行里：分支名常常很长，挤在那一行会把模型 / 思考挤到第二行。「改动」视图没有输入框时它在底部单独一行；已归档的会话在「已归档」条的最前面；手机（< 768px）上它和其他选项一起在「⚙」底部弹层里。在项目目录本身工作的 git 会话只显示分支名（`git_status.branch`）和未提交数，不显示 base。

#### 信息面板

右栏只有**概览**（下面原有的内容）。**改动**不放在右栏里：开发者要看全部文件和 diff，需要一整块地方。

**改动**视图：会话在 git 仓库里时，顶栏右侧有「聊天 / 改动」开关（`main-view`，`main-view-chat` / `main-view-changes`，各带图标；有未提交文件时「改动」后面显示文件数 `main-view-changes-count`，即 `git_status.uncommitted`；手机上只显示图标），点分支 chip 也切过去。它是和聊天区一样大的主视图，占满顶栏以下的全部空间；消息流和输入框让出位置（草稿在 store 里，切回来还在；审批横幅仍显示，点「查看」会切回聊天）。默认停在聊天，选择只对当前会话有效。内容：

- 顶部一行状态：分支 ← base、ahead / behind、未提交、冲突；上游和未推送数；PR（有的话）：`PR #12 · 已打开 · ✓3 ✗1 ⏳2`，点开在新标签页打开 `url`（`rel="noopener noreferrer"`）。PR 只在进入这个视图和点「刷新」时查（`include_pr: true`），其余刷新不查
- 操作（按钮 + 「更多」菜单）：
  - **同步 base**（worktree 会话，`behind > 0` 时高亮）：`session.sync_base`；`uncommitted_changes` 时提示「先提交或丢弃未提交的改动」并提供「让 agent 提交」；`conflicts` 时显示冲突文件 + 「让 agent 解决」「放弃合并」（`abort: true`）；`merging` 状态下按钮换成这两个
  - **让 agent 提交**、**创建 PR**、**让 agent 解决冲突**：快捷消息，经 `session.send` 发给 agent（turn 在跑时进入排队，和普通消息一样）。文案按界面语言，带上分支和 base，例如「把当前的改动提交到分支 anycon/x，提交信息概括改了什么」「把分支 anycon/x 推送到远端，用 gh pr create 向 main 开一个 PR，写清楚标题和描述」（base 是提交而不是分支时——`base` 是 `base_sha` 的前 12 位——不写目标分支，让 agent 用仓库的默认分支）「合并 main 时出现了冲突，解决 `git status` 里标为冲突的文件并完成合并提交」（不把仓库里的文件名拼进用户消息）。推送和 `gh` 走 agent 的权限审批
  - **刷新**
- 分段控件「相对 base / 未提交」（在项目目录本身工作的会话只有「未提交」），下面是文件列表（`session.diff`）：路径、状态（新增 / 修改 / 删除 / 改名，`untracked` 标「未跟踪」）、`+N −M`，二进制标「二进制」；点一个文件展开它的 diff（`session.diff { path }` → 复用 `DiffView`），`patch_truncated` 时提示「只显示了前 256 KiB」。`truncated` 时列表底部提示
- 刷新时机同分支 chip；切换会话时清空。进入这个视图时先出 git 状态，再单独发一次 `include_pr` 请求出 PR
- 已归档的会话：快捷消息和「同步 base」禁用（先取消归档）；worktree 不是 `active` / `kept`（创建中 / 不见了 / 已删除 / 没建成）时只显示说明

**概览**标签：

- 「会话」卡片：项目、工作目录、分支、创建时间，以及会话里不是 agent 默认值的选项（`ConfigOption`，如 Claude Code 的 Advisor model；名称是选项的 `label`，值是选项名 / 开 / 原文，`text` 的空串不算），每项一行名称、一行值；选项只显示、不能改（改在输入框下面的「更多」里）。值整段显示（长路径和分支名折行，不截断、不靠悬停提示），可以选中；工作目录和分支的名称右边有复制按钮（`info-workdir-copy`、`info-branch-copy`）。工作目录的名称右边还有一个打开按钮（`info-workdir-link`），打开它的文件浏览（§ 4.7）：worktree 会话进 `<项目名>/<worktree 相对路径>`（`active` / `kept` 以外的状态，目录还没建好或已经删了，退到项目目录），在项目目录里工作的会话进 `<项目名>`，scratch 会话进 `.scratch/<会话 id>`（daemon 的 `fs.*` 不拒绝这些带 `.` 开头的段，daemon.md § 10）；项目已不在列表里、或项目目录不在了（`missing`）时没有可打开的目录，只显示文字
- 「Agent」卡片（`info-agents`）：标题右边是正在工作的个数（主 agent 在跑一个 turn 或等审批算一个，加上还没结束的子 agent 和后台命令），没有就不显示。第一行是主 agent：名称、累计 token（输入 / 输出）、会话状态 chip。下面是已加载的事件里的子 agent（`category = subagent` 的调用），父在前、子按嵌套层数缩进：说明、agent 报的 token（`tool_result.detail.total_tokens`，结束后才有）和它调了几次工具、状态 chip（运行中 / 后台运行 / 已完成 / 失败 / 已停止）。状态：调用没有结果是运行中；有结果时，挂着任务（`task.tool_id` 指向它）的以任务为准——有任务在 `running` 是后台运行（会话没在跑、`background_tasks == 0` 时是已停止），否则有 `failed` 的是失败、其余（完成 / 已取消）是已完成；没有任务的看结果：带 `detail.background` 是后台运行，`is_error` 是失败，其余已完成。没有结果的子 agent 在主 agent 的 turn 结束后（或启动它的子 agent 结束后）算「已停止」，后台子 agent 在 agent 进程退出（`ended` / `error` / `interrupted`）后同样算「已停止」。子 agent 超过 6 个时只列还在跑的和最近的 6 个，上面一行「显示更早的 N 个子 agent」展开全部。子 agent 下面是还在后台跑的调用（不是子 agent 的调用里，状态判为后台运行的：挂着在跑的任务——如 `Workflow`——或者结果带 `detail.background` 还没补上最终结果的后台命令；agent 进程退出后不再列）：命令说明或 `$ 命令`（其它调用是标题）、「后台运行」chip，结束了就不再列。`SessionSummary.background_tasks` 比认出来的后台子 agent 和后台命令多时（事件不在已加载的历史里、daemon 旧了不标后台命令），多出来的另起一行「另外 N 个后台任务」（一个都没认出来时是「N 个后台任务」），也算进正在工作的个数。卡片上显示的 token 数一变（主 agent 的累计、子 agent 报的），卡片背景从左到右扫过一道淡淡的强调色（约 1.2 秒）；主 agent 的 token 只在 `turn_done` 才有新数，所以 turn 进行中（`running` / 等审批）事件流每来新事件也算一次。两道之间至少隔一道的时长：连续输出时一道接一道，停下来之后不再动。`prefers-reduced-motion` 时不显示
- turn 数、累计费用（主 agent 的 token 不含子 agent 的，费用是 agent 报的总数）
- 上下文占用（最近一个带 `usage.context_window` 和 `context_tokens` 的 `turn_done`）：一条进度条加「百分比 · 已用 / 窗口」（如 `23% · 46k / 200k`），agent 不报时不显示这一行。`context_tokens` 是 turn 结束时窗口里的 token 数，不是累计用量
- 「账号额度」卡片（`info-limits`，标题右边是 agent 名）：最近一个带 `usage.limits` 的 `turn_done` 报的账号用量窗口（[protocol.md § 6](../protocol.md#6-会话事件)），每个窗口一行：名称（300 分钟是「5 小时额度」，10080 分钟是「周额度」，其它长度按天 / 小时 / 分钟写，不知道长度的是「用量额度」；按模型的窗口后面带模型名）、「百分比 · 恢复时间」（当天只写时间，其它日子带月日；没有恢复时间只写百分比）和一条进度条，颜色的分档同上下文占用。数字是那个 turn 结束时的，账号的其它会话也在消耗同一份额度；恢复时间已经过了的窗口不显示（现在是多少不知道），一个都不剩或 agent 不报（API key 登录、ACP agent）时没有这张卡片
- 待审批请求列表（和消息流里的卡片联动）
- 操作：重命名、归档、删除（二次确认，说明会删 daemon 上的历史）、导出 Markdown
  - 导出 Markdown 时 `notice` 一条写成一行引用（`> **Warning** (<code>): <agent 的原文>`，原文折成一行、最长 500 字符；没有原文时用 `model_from` / `model_to` 等字段拼一句），`command_output`（`/context` 等本地命令）是一个代码块；后台任务（`task`）每个一行，写导出时的最终快照：名字、种类、状态、agent 完成数 / 总数、token / 工具调用 / 用时，挂在启动它的工具行后面（对不上工具行的在第一次出现的位置）。导出里的标题都是英文，这些行也一样
- **有 worktree 的会话**：「归档」先弹确认框：说明 worktree 的处理（`auto`：没有未提交的改动就删掉 worktree——分支上有自己的提交就保留分支，没有就一起删；有未提交的改动就保留 worktree），选项「自动 / 保留 worktree / 删除 worktree（丢弃 N 个未提交的改动）」，N 来自 `git_status.uncommitted`。「删除」确认框多两项：worktree 同样三选一；「同时删除分支 anycon/x」复选框，分支上有自己的提交（`ahead > 0`）或没推送的提交时在旁边警告「N 个提交会丢失」。没有 worktree 的会话、worktree 已经 `removed` / `failed` 的会话行为不变（归档不弹框）

### 4.6.1 待处理和未读

会话多了以后，一个跑了很久的会话结束后会沉到列表后面。两个标注帮用户找回它们（取舍见 [ADR-53](../decisions.md#adr-53-会话标注待处理是布尔标记未读是已读水位都和归档分开)）。

**数据**：daemon 在会话上存 `follow_up`（布尔）和 `read_seq`（已读水位，只增不减），随 `SessionSummary` 和 `session.changed` 到达所有设备，也进 IndexedDB 的 `summary`。改它们不动 `updated_at_ms`。`features/session/marks.ts` 从摘要算出显示用的状态，不另存。

**待处理**（用户手动标）：
- 两种显示由会话状态推出：`running` / `starting` / `queued` / `waiting_permission` 时是「完成后提醒」（空心旗），其余是「待处理」（实心旗，蓝色 `info` 色，和待审批的黄色区分）。给已经停下来的会话标一下，直接就是「待处理」，相当于「稍后处理」书签。归档的会话不显示标记也不计数，标记本身保留。
- 只有显式操作才清除：「已处理」或取消标记。**打开会话、给会话发新消息都不清除**（发新消息后它变回「完成后提醒」，下一轮停下来再提醒）。
- 入口：「待处理」页里这个会话那一行的「已处理」；会话页顶栏的旗标按钮（`follow-up-toggle`，`aria-pressed`）；宽屏时输入框上方靠右的「完成后提醒我」（`follow-up-chip`，标了之后换成下面的条；窄屏没有这一处）；输入区上方的条（`follow-up-bar`，归档的会话没有）：还在跑时写「这个会话结束后会通知你」+「取消标记」，停下来后写「这个会话在等你处理」+「已处理」；项目页和节点首页会话行最右的旗标按钮（`session-follow-up-toggle`）；⌘K 里的「标记为待处理 / 取消待处理标记」（§ 9.1，只在会话页、会话没归档、节点在线时出现）。节点离线时这些入口禁用。点击先改本地，请求（`session.set_marks`）失败就改回去并弹 toast。
- 提醒：停下来的待处理会话是「待处理」页「现在」段里的一条（[§ 4.11](#411-待处理-inbox)：已经在等审批的会话不重复列，等得最久的在最前，行上「打开」和「已处理」，「已处理」清掉标记）；还在跑的（「完成后提醒」）不在「现在」里，在页面底部折叠的「进行中」里；项目页筛选「待处理（n）」；标签页标题前缀和 `setAppBadge` 的计数 = 「现在」段的条数（[§ 7](#7-通知)；具体算哪些见 § 4.11；未读不计入）；会话从运行变成停下来时，页面在前台弹 toast「「标题」已结束，等你处理」，带「查看」（正在看着这个会话时不弹）；页面在后台时由 daemon 发 `follow_up` 通知（[daemon.md § 14](daemon.md#14-通知触发)），经 hub 变成 Web Push（§ 7）。

**未读**（自动）：会话不在 `running` / `starting` / `queued` / `waiting_permission`、没归档，且 `last_seq > read_seq`。运行中不亮（流式输出时 `last_seq` 一直在涨）。亮的时候列表行和左栏行的标题加粗、后面一个红点（当前打开的那个会话在左栏里不亮）。本地缓存是旧版本写的、没有水位时当作已读，升级后旧会话不会一起亮。

**已读上报**：会话页开着、页面可见、会话没在跑、已经显示到的最大 seq 超过 `read_seq` 时，停 300 ms 后发 `session.mark_read { session_id, seq }`。运行中不报（流式时每个事件一次请求太碎），停下来时报一次；页面在后台不报；离开会话页（或换会话）时把看到的最后位置补报一次。本地先抬水位、红点立刻消失，请求失败只记一条警告（下次打开会话还会再报）；节点离线时不报。新建会话的 `read_seq` 从 0 开始，由正在看着它的创建页上报；其他设备（或 CLI）建的会话没人看就保持未读。

### 4.7 文件浏览 `/n/:node/files/*`

只读：不能改、建、删、上传；预览头部有「下载」，把文件存到本机（见下面「下载」）。数据来自 daemon 的 `fs.list` / `fs.read`（[protocol.md § 5.3](../protocol.md#53-文件只读浏览)），路径只能在 workspace 根目录和关联项目目录之内，这条限制由 daemon 保证（越界返回 `forbidden`，[daemon.md § 10、§ 16](daemon.md)），Web 不做第二套判断。文件内容和消息一样走 E2E 加密的通道，hub 只看到元数据（Web UI 的代码由 hub 下发，见 [ADR-32](../decisions.md#adr-32-如实声明web-客户端代码由-hub-下发)）。

**入口**：项目页的「文件」按钮（§ 4.5）；会话信息面板里可点的工作目录（§ 4.6）；`/n/:node/files`（空路径）是节点上的项目列表，关联项目也在里面，目录不在了（`missing`）的项目灰掉、不能点；头部面包屑的「文件」回到这里。

**路径和 URL**：URL 的 `*` 整个就是 `fs.list` / `fs.read` 的 `path`。选中的文件、目录都在 URL 里：点文件、点面包屑、点 Markdown 里的链接都是改 URL，刷新、分享链接（对方也要配对过这台节点）都回到同一个地方。目录树的根是项目目录（`<项目名>`），scratch 会话的 `.scratch/<会话 id>` 自己是一个根，名字显示会话标题。路径里的 `..` 原样交给 daemon 判断。

**布局**（§ 3）：左边目录树（桌面 / 平板 288–320px 宽），右边预览。头部右侧两个按钮：「隐藏文件」开关（`files-hidden-toggle`，眼睛图标，记在 localStorage 的偏好 `filesShowHidden`，默认关）和「刷新」（`files-refresh`，重新读所有读过的目录和当前文件，节点离线时禁用）。头部下面是路径面包屑（`files-path`）：树根显示项目名，每一级都可点，回到那一级目录；最后一级是当前选中的，不是链接。手机上树和预览是两屏（§ 3.3），不并排。

**目录树**：根一开始就展开；子目录第一次展开才 `fs.list`（`files-row`，点一下展开 / 收起，收起再展开不重读）；目录在前、再按名字排（不区分大小写、数字按大小比），顺序由客户端排，不依赖 daemon 的顺序。URL 指向的路径上面的每一级会自动展开，选中的行高亮并滚进视野。以 `.` 开头的文件和目录默认不显示，开了「隐藏文件」才显示——**但 URL 指向的路径上的隐藏目录总是显示**，否则 worktree（在 `<项目>/.anycon/worktrees/<名字>`）看不到。键盘（WAI-ARIA tree，只有一行在 Tab 顺序里）：↑ / ↓ 上下移动，→ 展开，已展开时进到第一个孩子，← 收起，已收起或是文件时回到父目录，Enter / Space 打开文件或展开 / 收起目录，Home / End 到头 / 尾。某个目录读不出来（`forbidden`、超时…）时，错误显示在它下面的一行，带「重试」，树的其余部分不受影响。

**预览**（右边）：按扩展名或文件名决定怎么显示，头部是文件名、大小和「复制路径」。

| 类型 | 显示 |
|---|---|
| 文本 | 带行号的代码，按扩展名用 shiki 高亮（语言见 `lib/highlight.ts`：TypeScript / JavaScript / JSON / Rust / Go / Python / shell / CSS / SCSS / HTML / XML / YAML / TOML / INI / SQL / C / C++ / Java / Kotlin / Swift / Ruby / Lua / Dockerfile / Makefile / diff / Markdown；`Dockerfile`、`Makefile`、`Cargo.lock` 按文件名认）。不认识的扩展名显示纯文本。**超过 200 000 个字符不高亮**（shiki 在主线程里跑，1 MiB 的文件会卡住页面），并提示「文件较大，已关闭语法高亮」。空文件说明「这个文件是空的」 |
| Markdown（`.md` / `.markdown`） | 默认渲染，头部有「渲染 / 源码」切换（切换不重新读）。复用消息的 `Markdown` 组件和它的全部安全设置：原始 HTML 不解释，外部链接 `target="_blank" rel="noopener noreferrer"`，远程图片是点击才加载的占位（§ 4.6 消息流）。**相对地址不让浏览器去请求**：相对图片（`![](img/a.png)`）进入视口才经 `fs.read` 取、显示成 `blob:` 图片；相对链接（`[x](../README.md#a)`）变成应用内链接，去文件浏览里对应的路径（`?query` 和 `#hash` 去掉）；`/x` 相对项目目录；走出项目目录的、`#锚点` 的链接显示为普通文字，走出项目目录的图片显示为说明文字；相对图片不是图片文件、读不到或太大时显示成「图片：<alt>」。超过 300 000 个字符的 Markdown 默认先看源码 |
| 图片（png / jpg / gif / webp / svg，另有 avif / bmp / ico） | `fs.read { encoding: "base64", max_bytes: 512 KiB, offset }` **一块一块顺序读**（同时只有一个请求在途），拼好后放进 `<img src="blob:…">`（卸载时 revoke）。分块是因为设备到 daemon 只有一条有序的传输：一个十几 MiB 的响应会让会话事件、审批请求、「停止」的回复都排在它后面（和附件的 blob 通道同一个道理，[ADR-35](../decisions.md#adr-35-图片附件经-blob-通道传到-daemon消息只带引用)「上传让路」），每块只占 512 KiB。第一块就带着文件总长：**超过 10 MiB 的不再往下读**（不显示，提示「这张图片太大，无法预览（N，上限 10 MiB）」；目录列表里的大小已经超限就连第一块也不取）。超过一块的图片，加载时显示进度（「已读 / 总共」和进度条）。每块都核对：`bytes`（文件总长）变了说明文件在读的过程中被改写，**从头重读一次**，再变就报「读取过程中文件被改动了，请重试」；块的 `offset` 回显、长度对不上、base64 坏了报「节点发来的数据无法读取」。换文件、关掉预览会中止，后面的块不再请求。**SVG 只通过 `<img>` 显示，不会内联进 DOM**，里面的脚本不会执行。浏览器解码失败时提示「无法显示」。旧 daemon 不认 `encoding`（回来没有 `data_base64`），或不认 `offset`（忽略它，回应里没有 `offset` 字段：只有整张图在第一块里读完才能用，否则同一块会被重复拼起来得到坏图）时，提示更新节点上的 daemon |
| 其他二进制（读回来 `binary = true`） | 「二进制文件，N 字节」，不显示内容 |

文本（含 Markdown 源码）最多读前 1 MiB（`max_bytes`）；文件更大时在预览上方提示「只显示了前 1.0 MiB（共 N）」，`bytes` 是文件总长。预览里的读取就是 `fs.read`，会进 daemon 的审计；分块读同一个文件时同一台设备 5 分钟内只记一条（daemon.md § 13）。

**下载**：预览头部的下载按钮（`file-download`）对文本、Markdown、图片和二进制都有。点了用 `fs.read { encoding: "base64", max_bytes: 512 KiB, offset }` 一块一块**顺序读**完（和图片预览同一套：每块核对 `offset` 和总长，读的过程中总长变了从头重读一次，旧 daemon 不认 `offset` 时提示更新），拼好后用 `application/octet-stream` 的 `Blob` 加 `<a download>` 存盘，文件名是文件的名字去掉不安全的字符。`text/html`、`image/svg+xml` 之类的文件因此不会在 Web UI 的源里被渲染或执行，和附件的下载一样。
- **上限 50 MiB**：整个文件要拼在内存里，一块 512 KiB 顺序读，再大的在浏览器里既慢又占内存。目录列表 / 预览已知大小超限的，按钮禁用，悬停提示「太大，无法在这里下载（N，上限 50 MiB）」；预览打开之后文件才长大的，读到第一块就知道总长，停下并提示，不再读后面的块。
- **进度和取消**：下载中按钮变成「已读 / 总共」，再点一下取消，后面的块不再请求，也不存盘；换文件、离开页面同样中止。失败给一条错误提示（原因同预览），再点按钮重试。
- 下载不绕过任何检查：路径边界、关联项目的复核、`forbidden` 都在 daemon 里，和预览读到的是同一份数据。

**选中一个目录**（面包屑、Markdown 链接、项目页 / 信息面板的入口指向的是目录）：桌面上右边显示这个目录的内容（名称、大小、修改时间，点开进入）；手机上显示树。不会自动打开 README。

**状态和错误**（§ 11）：
- 节点离线：没有读到过的内容显示「节点离线」整块说明（读不了），不是错误；节点重新上线后，因为链路问题失败的目录和文件自动重读。读到过的目录和文件在断线期间还留在页面上。
- 路径不存在（项目被移走、文件被删、会话的 scratch 目录已清理）：「节点上没有这个路径，可能已被移动或删除」，带重试；daemon 拒绝访问（`forbidden`）、不是普通文件或目录（`invalid`）各有自己的说法，超时、连接中断沿用通用文案。根目录读不出来时整页是这个错误，不渲染树。
- 读单个文件失败只影响预览，树照常。
- 页面里的数据都不进 IndexedDB，也不跨页面缓存：离开页面就丢，下次进来重新读，因为节点上的文件随时会变（agent 在改）；页面里没有自动轮询，要看最新的点「刷新」。

**限制**：只读；单文件文本最多 1 MiB、图片预览最多 10 MiB、下载最多 50 MiB（每块 512 KiB，最多 100 个请求）；文件在读的过程中被改写成**同样长度**时检测不到（只比较总长），图片预览和下载的文件可能由新旧内容拼成；没有搜索、没有文件内跳转（行号锚点）、没有 diff（改动在会话页的「改动」视图，§ 4.6）；目录列表不分页（daemon 一次返回整个目录）；不按 `.gitignore` 过滤（`node_modules` 之类也会列出来，展开才读）。

### 4.8 节点设置 `/n/:node/settings`

| 标签 | 内容 |
|---|---|
| **Agent** | `agent.list` 的结果：每个 agent 一张卡，状态（就绪 / 未安装 / 未登录 / 版本过低 / 异常）、版本、路径、问题提示和修复建议（「在那台机器上运行 `claude` 完成登录」）。「重新检测」按钮。每个就绪的 agent 下可设置**该节点上的默认选项**（模型、思考、权限模式），存在 daemon（`node.set_agent_defaults`） |
| **设备** | 和这台 daemon 配对的设备列表、在线状态、吊销。「添加设备」→ 让 daemon `pair_begin`（`node.pair_begin { long }`），页面上显示短码和二维码（链接是 `/pair#code=…`）。对话框里有「长码（16 位）」开关，默认开（`long: true`，二维码 / 链接带的就是 16 位码，经公共 hub 配对时用它）；关掉则重新请求一个 8 位短码（每次切换都会重新请求，新的顶掉旧的登记）。hub 拒绝登记（`node.pair_begin` 回 `busy` 且 `data.reason` 是 `quota` 或 `rate_limited`，或 `forbidden` 且 `data.reason` 是 `forbidden`）时对话框不关，里面写原因：`quota` 在登记时只可能是每日配对次数，说名额随 24 小时滚动窗口回来、带去「设置 → 配额」的链接（不叫用户去移除设备：设备数 / 节点数的上限要到配对收尾才检查），`rate_limited` 让用户等一分钟，`forbidden` 说 hub 不允许这个节点发起配对；别的错误（含没有 `data.reason` 的 `forbidden`）照旧弹提示、关对话框。吊销是两步：hub 侧撤路由 + daemon 删公钥（`node.revoke_device`），任一步失败都显示错误，不吞。被吊销的浏览器下次连接看到「需要重新配对」，重新配对即可。「添加设备」对话框分两页：**短码**（上面的内容）和**接入码**（ADR-36：`node.enroll_code` 生成的 6 位码，大号显示 + 5 分钟倒计时 + 一句「新设备登录同一账号，选这台节点 →「我有接入码」」；关掉对话框不作废，过期后可重新生成，新的顶掉旧的）。另有「扫码批准新设备」按钮（§ 4.3.2） |
| **接入** | ADR-36。**节点口令**：状态（未设置 / 已启用 / 已停用 / 已锁定、连续失败次数、下次允许尝试的时间、设置时间和设置者，`node.enroll_status`）；「设置口令」/「修改口令」（两次输入、至少 8 个字符、`autocomplete="new-password"`，`node.set_enroll_password`）；「清除口令」（确认）；启用 / 停用开关（`node.set_enroll_enabled { password }`）。锁定时显示红色说明和「重新启用」，确认框写「连续 10 次输错可能是有人在猜。确认是你自己输错的再启用；不确定就先改口令」。**批准接入**开关（`node.set_enroll_enabled { approval }`，关掉后扫码批准和接入码都不可用）。**待批准的接入请求**（`node.enroll_list`，每条可批准 / 拒绝，和批准对话框同一套）。**最近的接入活动**（`node.audit` 里的 `enroll.*`，最近 20 条） |
| **Workspace** | workspace 根（只有一个根时一行「Workspace root」；多个根时每个根一行，主根标「默认」，额外根标「额外的 workspace 根」，`available = false` 的根标「不可用」并提示是不是磁盘没挂上、修好之后重启节点）、项目数、回收站内容（可恢复 / 清空；多个根时每条标出来自哪个根，还原回原来的根）、scratch 目录大小。**Worktree** 一节（`workspace.worktrees`，ADR-34）：每行项目、分支、所属会话（链接；会话已删除时「没有会话」）、状态（使用中 / 已保留 / 已删除 / 不见了）、未提交数、自己的提交数、大小、创建时间；「删除」（`workspace.remove_worktree`）：会话还没归档的禁用并提示「先归档会话」；确认框里有未提交改动时要勾「丢弃未提交的改动」（`force`），另有「同时删除分支」（`delete_branch`，`ahead > 0` 时警告） |

| **关于** | daemon 版本、协议版本、运行时长、数据库大小、「检查更新」、「查看日志」。**查看日志**（`node.logs`，daemon.md § 17）打开对话框：按最低级别过滤（默认 info 及以上；trace / debug / info / 警告 / 错误）、选行数（200 / 500 / 1000，默认 500）、「刷新」、「复制」（复制当前显示的全部行）；等宽字体、旧的在上、读完滚到最下面；`truncated` 时注明「更早的行没有显示」；没有日志时说明「这个级别下没有日志」；读取失败显示原因。日志里可能带会话文字的行节点已经去掉了，这里原样显示。节点离线时按钮禁用。下面是「移除这台节点」：给重装了、不再用了的机器，节点离线也能用。确认框写明 hub 不再为它转发连接并删掉它的所有配对、这个浏览器忘记它（配对记录和会话缓存）、那台机器上的项目和会话历史不会被删除、要再用它得在那台机器上 `anycon init --force` 后重新配对。确认后先 `DELETE /api/devices/:id`（404 当作已完成），刷新设备列表，再忘记，然后回 `/`；hub 那一步失败就什么都不动，显示错误，可以重试。账号里别的浏览器之后按 § 2 看到「已从账号移除」 |

### 4.11 待处理 `/inbox`

应用的首页：所有等用户的事放在一个队列里（设计取舍见 [ADR-55](../decisions.md#adr-55-web-ui-以待处理为首页手机用底部标签栏分身不是一个聊天窗口)，整体设计见 [§ 14](#14-加入清单和分身之后的界面)）。数据全部来自 store 里已有的东西，合并左栏节点过滤器勾选的节点；计算在 `features/inbox/derive.ts`，页面、导航项、应用角标共用同一个结果。

**「现在」段**，有这些条目，每条行上都有文字标签（审批 / 计划 / 提问 / 接入请求 / 待处理 / 出错 / 等待审批（缓存）），不只靠颜色：

| 条目 | 来源 | 行内 |
|---|---|---|
| 权限请求、计划、提问 | `permission.list` / `permission.request`（`kind` 为 `tool` / `mode_change` / `other` 的是审批，`plan`、`question` 各自一类） | 展开才有按钮，见下 |
| 接入请求 | `node.enroll_list`，等已配对设备批准的那些（和 § 3.4 的横幅同一个口径） | 「查看」，打开 § 4.3.2 的批准对话框 |
| 等待审批（缓存） | 会话摘要说它在等审批（`status = waiting_permission` 或 `pending_permissions > 0`），但这个页面里还没有那条请求（刷新后还没同步完、节点离线）。摘要来自 IndexedDB 的缓存，请求的详情只有节点连着、请求到了之后才有 | 只有「打开」，没有答复按钮；行上写「等待审批（缓存）」。请求到了之后由真正的请求条目取代它，不重复计数 |
| 标了「待处理」的会话 | `follow_up` 且已经停下来（§ 4.6.1）：没归档，不是已经在等审批的会话 | 「打开」「已处理」（清掉标记，`session.set_marks`） |
| 出错的会话 | 没归档、`status = error`、`updated_at_ms` 在最近 7 天内；`interrupted` 不算；不另存「已忽略」 | 「打开」「归档」（有 worktree 的会话先弹 § 4.6 的归档确认框） |

- 同一个会话既标了「待处理」又出错时只列一条，按「待处理」算；清掉标记后它仍在 7 天内，就以出错的身份留下。未读（红点）不是条目：它只管「看过没有」
- **排序**：有到期时间的（请求的 `expires_at_ms`、接入请求的有效期）在前，先到期的在前；其余按等待时长，等得最久的在前（请求按 `created_at_ms`，会话按 `updated_at_ms`）；时间相同按 key，顺序稳定
- **数字**：「现在」段的条数，在导航项、手机标签栏、窄条、应用角标和标签页标题上是同一个数，**只算左栏节点过滤器勾选的节点**（旧版的角标不看过滤器、算所有节点）。包括：待答复的请求（含计划、提问）、接入请求、停下来的待处理会话、最近 7 天出错的会话、等待审批（缓存）的会话；不包括还在跑的会话、未读。没勾选的节点上「现在」段有条目时，节点过滤器的按钮上有一个小点（有文字说明「过滤器之外的节点上有 N 件在等」，不只靠颜色），数字本身不变。数字只在输入变了时重算（会话摘要里和待处理有关的字段、请求、接入请求、过滤器），不为打开的会话每一条流式事件重算；有接入请求在倒计时时每秒一次，否则每分钟一次（出错会话的 7 天期限）
- **「进行中」**：页面底部折叠成一行（数量），点开列出还在跑的会话（`running` / `starting` / `queued`；归档的、已经以权限请求列在「现在」里的、在等审批的——那些是「现在」里的「等待审批（缓存）」——除外），标了「完成后提醒」的写明。没有等用户的事时，上面是「没有等你的事」（焦点落在这个标题上），「进行中」照常在下面
- 页面的段和条目类型是可扩展的结构（`SECTIONS`、`InboxItem`）：「待验收」「稍后」段和对应的条目到数据有了再加，现在页面上没有它们，也没有清单、「记一项」、空间切换的入口

**权限请求的详情和答复**：详情里用的是会话页同一个 `PermissionCard`（§ 4.6），内容完全一样——命令、工作目录、全部选项，以及「现在」里额外的上下文：节点、所属会话、项目、等了多久、「打开会话」链接。**没有不看详情就能答复的入口**：行上没有任何答复按钮；没有滑动操作；通知上也没有（§ 7）。

- 桌面（≥ 1200px）：左边列表（360px）、右边详情，没有右栏。默认选中第一条，选中的那一行 `aria-current`；右半边是选中那条的详情
- 平板（768–1199px）：列表占满中栏，点一行详情从右边滑出（Radix 对话框，焦点陷在里面，Esc 或「关闭详情」收起）
- 手机（< 768px）：单栏，点一行在行内展开 / 收起（`aria-expanded`）。「现在」段的第一条默认展开，这个决定只做一次：页面在眼前、而且数据到了（有条目，或者勾选的节点都同步完了仍然没有）的时候。冷启动时同步还没完，条目晚到，照样展开第一条；同步完之后页面是空的，后来才到的条目不会被替用户展开；页面藏在后面（别的标签页）时也不展开。之后列表怎么变都不替用户展开别的
- **选中跟着条目，不跟位置**：选中和展开记的是条目的 key，前面插进来或重排的新条目不改变正在看的那条。平板上详情只在用户操作（点一行、深链接）之后才滑出，窗口从宽屏缩到平板时自动选中的那条不会弹出来
- **处理完一条**：只有「在这个页面上处理的」选中和焦点才落到下一条（列表里它原来的位置；最后一条就落到前一条；跳过「等待审批（缓存）」）；全部清完焦点落到「没有等你的事」。手机上下一条同时展开。「在这个页面上处理」指：「待处理」页**在眼前时**点了答复按钮、按了 `⌘⇧A` / `⌘⇧D`、「已处理」、「归档」，或者在接入对话框里**点了**批准 / 拒绝（只打开对话框又取消不算）。手机上「待处理」藏在后面时（比如从它展开的请求进了会话页，在会话页答复了同一个请求）不算：对「待处理」来说那是别处处理的
- **用别的方式离开的**（别的设备答复了、在会话页答复了、请求过期了、待处理标记被清掉、出错的会话被归档或过了 7 天、接入请求过期了）：不替用户挑下一条——下一条的按钮会立刻可点，而用户没看过它的内容。选中的那一处（桌面右半边、平板的抽屉、手机展开的那一行原来的位置）换成占位「这一条已经不在等你了」，带「下一条」按钮和「打开会话」链接，用户点了「下一条」才选中它。例外：条目是因为用户自己改了左栏节点过滤器才离开列表的，直接清掉选中，不留占位
- **新显示的请求先锁一会儿**：详情里显示的请求换了（点了别的行、处理完前进、深链接、「下一条」），答复按钮和 `⌘⇧A` / `⌘⇧D` 先锁 600 毫秒（`ARM_DELAY_MS`），按钮是禁用的，按键什么都不做；连点、连按的第二下不会落到补位上来的那条头上。页面从藏着变回在眼前（手机上切回「待处理」标签页）也重新计时
- **同一个请求只答复一次**：按钮和快捷键共用「正在答复」记录（按请求 id），已经在答复的请求再来一次直接丢掉；会话页的卡片也用它
- **离线节点**：节点不在线（`conn` 不是 `ready`）时它的条目是上次的缓存：行上有「缓存」标签，详情里一段说明「节点离线，这是它上次报告的内容，节点回来之后才能答复」；答复、「已处理」、「归档」的按钮禁用，「打开」照常。待答复请求只在内存里（`permission.list` 每次连接重拉），所以刷新页面后离线节点的请求不再有，会话类条目（包括「等待审批（缓存）」）来自 IndexedDB 里的缓存；**缓存的是会话摘要，请求的详情不缓存**
- **从通知进来**（`/inbox?node=&session=`）：定位那个会话最早的一条待答复请求并选中 / 展开（推送只带类别、节点和会话，不带请求 id：同一个会话同时有几条时，定位到的可能不是触发这条通知的那一条，[ADR-55](../decisions.md#adr-55-web-ui-以待处理为首页手机用底部标签栏分身不是一个聊天窗口)）。页面读到参数就把它们从地址里去掉（不管请求到没到）。目标不受节点过滤器限制：那个节点没勾选时照常显示，条目放在列表最前面，写明「不在你勾选的节点里，不计入数字」，并给「显示这个节点」按钮（勾上它；不自动切换）。节点还在连或没同步完时显示「正在等 <节点> 连上…」；节点离线时说它离线、回来之后请求会出现在这里；节点不再认识这个浏览器（`noise_failed`）时说要重新解锁，给「去解锁」。同步完之后找到就选中（链接打开之后用户自己选了别的，就不抢他的选中），找不到说明「这个请求已经处理过了」并给「打开会话」；这个浏览器没解锁或不认识的节点单独说明，给「去解锁」和「配对节点」入口，不说「已处理」。详情旁边始终有「打开会话」
- **键盘**（桌面，§ 9）：`J` / `K` 上下移动选中并把焦点放到那一行，`Enter` 把焦点移进详情，`⌘⇧A` / `⌘⇧D` 作用于选中的那条权限请求（限制同会话页，另外：有对话框或菜单开着、节点不在线、新显示的头 600 毫秒内都不答复）。「卡片是否在屏幕上」只认真正看得见的那一份：手机上藏起来的标签页里的同一张卡片（`inert`）不算
- 页面常驻时（手机标签页被藏起来）不处理快捷键和焦点

**升级说明**：已经用过旧版本的浏览器（localStorage 里已有偏好、没有 `homeNoticeSeen`）第一次打开新版本，弹一次对话框：首页换成了「待处理」，原来的节点首页在哪里（桌面：节点下拉里的「节点首页」；手机：「更多 → 节点」）。关掉（按钮、×、Esc）就记为看过；第一次启动时没有任何偏好的新用户直接记为看过。从通知点进「待处理」里某条请求时先不弹，等用户离开那条请求之后（或下一次平常打开）再说，免得说明盖住要答复的请求。

**状态播报**：「现在」的数字一变，读出完整的一句话（§ 7）。启动和重连同步期间不播：勾选的节点都同步完（或确认不会有同步：离线、不认识这个浏览器、协议版本不兼容）之后才取基线，同步进行中数字怎么变都不播，同步完再取基线，之后的真实变化才播。有节点 15 秒还定不下来（第一次同步失败、卡在连接上）就不再等它，照常取基线。

**相对时间**（「3 分钟前」）每分钟刷新一次，各行共用一个节拍；数字模型本身在条目没变时不重算，不随时间重渲染。

## 5. 模型、思考、权限模式

这是用户最常碰的三个选项，值得单独说。

### 5.1 数据从哪来

**Web UI 不内置任何 agent 知识。** 一切来自 daemon 的 `agent.list`（`AgentInfo`，结构见 [daemon.md § 5.2](daemon.md#52-agentinfo)），和 UI 相关的三块：

```
models: [ { id: "claude-opus-5-5", label: "Opus 5.5", description, default: true,
            thinking: { options: [ low | medium | high | xhigh | max ], default: "medium" } },
          { id: "claude-haiku-4-5", label: "Haiku 4.5", thinking: null } ]
allow_custom_model: true
modes:  [ { id: "default",           label: "Always Ask",        default: true, risk: "normal" },
          { id: "acceptEdits",       label: "Accept File Edits",                risk: "normal" },
          { id: "plan",              label: "Plan Mode",                        risk: "safe" },
          { id: "bypassPermissions", label: "Bypass",                           risk: "dangerous" } ]
options: [ { id: "fast_mode", kind: "bool", label: "Fast mode", default: false } ]
```

要点：**思考等级挂在模型上**（不同模型支持的等级不同，有的不能关）；**权限模式是 agent 自己的集合**（Claude Code 六种、Codex 四种、ACP agent 自定义），UI 只认 `risk`；其他选项走通用 `ConfigOption`，折叠进「更多选项」。新 agent 多一个模式或选项不需要改 Web UI。

### 5.2 控件

| 选项 | 控件 | 细节 |
|---|---|---|
| 模型 | 下拉 | 显示 `label`，副标题 `description`，默认项有标记，`tags` 里的 `1m` 之类显示为小徽章。`allow_custom_model` 时底部有「自定义…」可输入任意 id，输入过的自定义值记在本地供下次选择。agent 只有一个模型时不显示 |
| 思考 | 下拉 | 显示**当前所选模型**的 `thinking.options`，切换模型时如果原等级不在新模型的列表里，回落到新模型的默认值并提示。等级名不翻译（low / high 是 agent 的词汇）。所选模型 `thinking` 为空时不显示 |
| 权限 | 下拉 | 显示 `modes[]` 的 `label` 和 `description`。`risk = dangerous` 的项带警示图标，选中时弹确认框说明风险，确认后头部状态 chip 变红并一直显示该模式名；节点禁止危险模式时（`allow_dangerous_modes = false`）daemon 已把这些项从 `agent.list` 的 `modes` 里去掉，所以通常根本不出现；若 `agent.list` 缓存过期、`session.set_settings` 仍被拒（`forbidden` / `invalid_settings { field: "mode" }`），该节点的危险项禁用并说明。`risk = safe`（如 plan）用绿色标识 |

### 5.3 什么时候能改

- **新建会话时**：composer 选项栏全部可改
- **会话空闲时**：全部可改（`session.set_settings`），从下一个 turn 生效，消息流出现「模型已切换为 …」。adapter 内部是热改还是重启进程续接，UI 不关心（[daemon.md § 6.4](daemon.md#64-会话中修改)）
- **运行中的 turn**：选项仍可改，但改动排队，本轮结束后才 `session.set_settings`。排队中、还没生效的那几格文字换成浅色，悬停说明「本轮结束后生效」；不在选项栏下面另加提示行（运行状态切换时布局不跳动）

### 5.4 默认值

优先级从高到低：

1. 用户在这个浏览器上，对这个 `(节点, agent)` 上次用的值（localStorage）
2. 节点设置里该 agent 的默认选项（存在 daemon，所有客户端共享）
3. agent 自己的默认（`choices[].default`）

例外：`risk = dangerous` 的权限模式**不会**被自动带进新会话——不管它来自「上次用的值」、节点默认值还是 `agent.list` 里的 `default` 标记，Web 在自动选择默认值时一律跳过危险模式（回落到下一级里的非危险项），危险模式每次都要显式选并确认。节点默认值（第 2 级）daemon 会反映到 `agent.list` 的 `default` 标记里，所有客户端都读得到；daemon 自己也不接受把危险模式写成默认值，除非 `allow_dangerous_modes` 允许（[daemon.md § 5.6](daemon.md#56-rpc)）。

### 5.5 思考过程的显示

`thinking_delta` 是否出现取决于 agent 是否输出（capabilities.`thinking_stream`）。显示策略在外观设置里：折叠（默认）/ 始终展开 / 隐藏。隐藏时仍然缓存，只是不渲染。

### 5.6 用量与费用

`turn_done.usage` 有什么就显示什么：token 数、费用、用时。agent 不报的字段不显示占位。会话累计显示在信息面板，子 agent 各自的 token（`tool_result.detail.total_tokens`）显示在它那一行；节点首页不汇总（daemon 不做记账，这是 agent 的事）。

## 6. 状态层与缓存

### 6.1 store 划分（zustand）

| store | 内容 | 持久化 |
|---|---|---|
| `auth` | 账号信息、登录方式 | 否（每次从 `/api/me` 拉） |
| `hub` | WebSocket 状态、本设备 id、配额 | 否 |
| `nodes` | 每个节点：Noise 会话状态、在线状态、`node.info`、`agent.list` 缓存 | `node.info` 和 `agent.list` 进 IndexedDB |
| `sessions` | 会话列表、每个会话的事件（按 seq） | IndexedDB |
| `drafts` | 每个会话的未发送消息和草稿 | IndexedDB |
| `prefs` | 外观（含左栏是否显示 Recent 组）、Enter 行为、各 `(节点, agent)` 的上次选项、右栏开合、「首页换成待处理」的说明是否看过（`homeNoticeSeen`） | localStorage |

hub 的 REST 接口用 TanStack Query，不进 zustand。命令面板的内容搜索结果（§ 9.1）只活在面板自己的组件状态里：不进 store、不写 IndexedDB，关掉面板就丢。

### 6.2 IndexedDB

```
keys        { device_id, device_token, device_token_issued_at_ms, static_keypair }   本设备 Noise 密钥、hub 签发的 device token 和它的签发时间（轮换见 § 6.4）
nodes       { node_id, name, info, agents, last_seen }
sessions    { session_id, node_id, project, agent, title, status, options, last_seq, updated_at, summary }   `summary` 是整份 `SessionSummary`，含 `follow_up` 和 `read_seq`（§ 4.6.1）
events      { [session_id, seq], event }                 主键是复合键，范围查询拉增量
drafts      { session_id, text, attachments?: [AttachmentRef], unsent: [{ …, attachments? }] }
blobs       { blob_id, bytes, mime, last_used_ms }       附件缓存（ADR-35、ADR-44：图片和下载过 / 上传过的文件），LRU 上限 200 MiB
```

按 origin 隔离，这是 [ADR-23](../decisions.md#adr-23-token-登录与局域网双-origin) 接受的代价。

`keys`（Noise 私钥、device token）和 `events`（会话明文缓存）是**明文**存的，在浏览器的存储保护之外没有额外加密。这些代码来自 hub（[architecture.md § 5.6](../architecture.md#56-威胁模型)），能读到它们；「退出登录」不清它们，「退出并移除本设备」才清（§ 4.9）。

### 6.3 同步算法

每次和某个节点建立 Noise 会话后：

1. `node.info` → 校验协议版本，更新能力。版本不兼容就停在这里
2. 其余几步**同时发出**，不互相等待：每个请求都要经过一次 浏览器 → hub → daemon 的往返，串行发会多花好几个往返时间；daemon 对同一客户端仍按到达顺序处理（protocol.md § 7.3）。某一步出错只影响它自己那块数据，链路断了整轮作废、重连后再来
   - `agent.list { if_none_match }` 刷新 agent 缓存；`workspace.list`（有 `workspace` 能力时）；`permission.list` 拉未决请求；`node.devices`；`node.enroll_list`
   - `session.list` → 和本地比对：新会话插入；`last_seq` 更大的标记需要增量；本地有而远端没有的标记已删除。比对完之后处理当前打开的会话（下一步要用比对结果判断缓存是否作废）
3. 当前打开的会话：`session.watch` 和 `session.history(after_seq)` 一起发（按到达顺序处理，watch 先生效，不会漏事件）；其他会话在打开时再拉。离开页面 `unwatch`。列表级变化（标题、状态、待审批数）通过 `session.changed` 推给所有在线客户端，不需要 watch
4. 全部完成后重发未发送的消息

连接各阶段（加载、连 hub、`auth_ok`、握手、就绪、每个同步请求、打开的会话就绪）用 `performance.mark` / `measure` 记录，名字带 `anycon:` 前缀，DevTools 的 Performance 面板可见；`localStorage['anycon.debug.timing'] = '1'` 时在控制台打印耗时表，控制台里 `anyconTiming()` 随时打印全部记录。只记阶段名、方法名和 id 前缀。

### 6.4 连接状态机（每个节点）

```
hub_disconnected → hub_connecting → hub_authed
    → peer_offline              （节点不在线，可看缓存、可写草稿）
    → noise_handshaking → ready （正常）
    → noise_failed              （daemon 不认识我们的公钥：被吊销或 daemon 重装，提示重新配对）
```

hub 重连用指数退避 1s → 30s 加抖动；收到 `4002 restarting` 用 1–3 秒。页面从后台回到前台（`visibilitychange`）立即触发一次重连检查，这对手机很重要。

**device token 轮换**（hub 侧规则见 [hub.md § 5](hub.md#5-设备与设备-token)）。device token 签发满 30 天就换一个，缩短泄露的 token 的有效期。`keys` 记录里的 `device_token_issued_at_ms` 是它的签发时间（配对 / 接入拿到它，或最近一次轮换的时刻）；没有这个字段的旧记录当作「很旧」，下次连上 hub 就轮换一次。

- **触发**：每次 `auth_ok` 之后，在用 device token 认证的连接上，token 到期（满 30 天；签发时间未知，或在「未来」——时钟被往回拨过，时间不可信——也算到期）就发 `rotate_token`。临时连接（没有 device token，只为配对而来）不发
- **重发和复查**：hub 同一设备 1 分钟内只轮换一次，多余的请求既不回复也没有失败通知，所以没等到回执就要重发：发出 75 秒后还没拿到新 token 就再发一次，一条连接上头 3 次都这样间隔 75 秒（轮换成功、或 token 不再到期后重新计数）；之后以及没到期时，每小时检查一次、到期就再发：一个一直开着的标签页超过 30 天也会轮换，hub 一直不回复（比如不支持轮换）时也只是每小时一帧。断开和停止时清掉定时器，新连接 `auth_ok` 后重新开始。重发有用的情形：请求被当作「太频繁」忽略了，或者回执在同一条连接上丢了（hub 记着这条连接用的已经是新 token）。**重连之后不行**：用旧 token 认证的连接不能轮换（[hub.md § 5](hub.md#5-设备与设备-token)），回执丢了、标签页又在 60 秒宽限内用旧 token 重连的话不能再请求，宽限一过要重新配对
- **落盘**：收到 `token_rotated` 后，新 token 和新的签发时间作为同一份 `keys` 记录一次写入 IndexedDB（单条记录的写入是原子的），内存里同时换上，之后的重连用新 token。新 token 只传这一次，所以写库失败也不回退，只在控制台报错——旧 token 只剩 60 秒，回退没有意义；这种情况下刷新页面之后可能要重新配对。没有 device token 的连接收到 `token_rotated` 一律忽略
- **多个标签页**：同一个 origin 的标签页共用 IndexedDB 里的一份身份，各自在内存里留一份副本；一个标签页轮换之后，别的标签页内存里还是旧 token。三道防护：① 写 `keys` 在一个读写事务里「读 → 合并 → 写」：库里的 token 签发时间严格更晚、且是同一个设备身份（Noise 公钥相同）时保留库里的 token（连同签发时间和设备 id），旧副本改设备名之类的写入盖不掉新 token；② 请求轮换之前先读一次库，库里有签发更晚的 token 就换上、不再重复轮换；③ 旧副本的 token 过了宽限，hub 回 `auth_fail { invalid }` 时先重读库，库里有不同的 token 就换上它、马上重连，不当作失效。库里没有不同的 token 才清除、停在「需要重新配对」，清除只在库里的 token 仍是被拒的那份时进行，不会抹掉别的标签页刚存的新 token。设备被吊销（`auth_fail { revoked }` / 关闭码 4004）时清掉内存里的 token；库里的 token 如果已经不是这份就不动，它下次被 hub 拒绝时再清

**配对完成的最后一步：`pair.ack`**。配对不是在 hub 发 `pair_done` 时结束的。握手成功、收到 `pair_done` 之后，浏览器用刚建立的 Noise 传输等 daemon 发来的第一条通知 `pair.ack`（`{ node_id, peer_id, name, version, fingerprint }`），逐项校验：`peer_id` 等于 hub 在 `pair_done` 里告诉自己的正式设备 id；`node_id` 等于 `pair_done.peer`；`fingerprint` 等于本地对握手得到的 daemon 静态公钥算出的指纹。全部通过才把节点（id、**认证过的**名称、公钥）写进 IndexedDB 并显示为已配对；节点名取 `pair.ack` 的，不取握手第 2 条里未经认证的那个。30 秒没收到、或任何一项对不上，就放弃，什么都不保存。本地已有同 id 但公钥不同的节点时不覆盖，提示用户先忘记旧节点。这样一个伪造 `pair_done` 的 hub 骗不了浏览器（它没有 PSK，造不出 `pair.ack`）。

**传输的分片与重置**。每个节点一个 Noise 传输和一个分片重组器。发：一条 RPC 的密文超过 200 KiB 就拆成多个 `data` 信封（每条 RPC 一个本地递增的 `msg_id`）。发出的 `data` 信封原文保留在一个 16 MiB 的**在途窗口**里：10 秒内发出的和等待重发的永不逐出，窗口满了新信封在出站队列里按序等（握手不受窗口限制），不逐出。收到 `backpressure { to, seq }` 只暂停**那个节点**（新信封排队，握手和其他节点照发），等 `retry_after_ms`（最近一条 `rate_limited` 给的，封顶 30 s；没有就 100–300 ms 加抖动）后把所有被退回的 `seq` 按升序原样重发（不重新加密），再放行排队的；`rate_limited` 暂停整条连接。被退回的 `seq` 已不在窗口里（10 秒后才到的退回）、或同一节点连续 60 秒都被退回 → 重置传输重新 IK。传输被丢弃时，这个节点排队中和被退回的信封一起丢掉并立刻释放原文，只留 10 秒的「seq → 节点」墓碑，迟到的退回不会重置新传输。**握手被退回**（hub 限速或缓冲满）不重置也不立即重发：等 300–1000 ms（逐轮翻倍、封顶 30 s，且不早于 `rate_limited` 过期）后原样重发同一条握手消息，等待期间握手超时不计时，所以长时间限速不会被误判成 `noise_failed`。收：分片按 `msg_id / index / count` 严格按序重组后再解密。**解密失败、分片乱序或收到 RESET（`0x02`）都意味着传输已失步**：丢掉这个节点的传输、清空重组器，直接重新发起 IK 握手（状态回到 `noise_handshaking`），不是整页报错。收到 `dropped { too_large }` 说明自己没分片，是 bug，记 console error。握手重试仍失败才进入 `noise_failed`。

### 6.5 加密在哪跑

Noise 的 wasm 在主线程跑：单条消息加解密是微秒级，开 Worker 得不偿失。例外是 Argon2id（短码配对和节点口令解锁各做一次，§ 4.3 / § 4.3.1；约 0.1–1 s、64 MiB wasm 内存）：目前也在主线程，调用前先让 UI 画出「正在派生密钥…」再算，手机上的实际耗时还没有实测；移到 Worker 是已知的改进项。接入用的 CPace 只是几次标量乘法，毫秒级，不用单独处理。附件分块（512 KiB 一块）的 base64 和加密也在主线程，块与块之间让出主线程，不卡输入。

## 7. 通知

- **Web Push**（ADR-37）：hub 只在这台浏览器**没有在线连接**时推（[hub.md § 6.1](hub.md#61-web-push)）。service worker 收到 `{ category, node, session }` → 从 IndexedDB 读本地缓存的节点名和会话标题组装文案（没有缓存就用「一个会话」/「一台节点」，文案逻辑和页面共用 `features/sync/pushText.ts`）→ `showNotification`（每条推送都要显示，`userVisibleOnly`）。通知的 `tag`：会话类是 `session:<会话 id>`（同一会话的各类别合并），第二行是「来自 <节点名>」。界面语言取页面记在独立 IndexedDB 库 `anycon-sw`（`kv.lang`）里的值，没有才跟 `navigator.language`；service worker 只读页面的主库、从不创建它。点击：有已打开的本 origin 窗口就聚焦，用 `postMessage({ type: 'anycon:navigate', url })` 让页面站内跳转，没有就 `openWindow`；`permission_requested` 打开 `/inbox?node=<短 id>&session=<会话 id>`（定位并展开那个会话最早的一条待答复请求，[§ 4.11](#411-待处理-inbox)；通知上没有允许 / 拒绝按钮：service worker 手里没有解密后的请求详情，在通知上答复等于不看内容就批准），其余会话类（`turn_finished`、`error`、`session_idle`、`follow_up`）打开 `/n/:node/s/:session`，接入类打开 `/n/:node/settings?tab=enroll`（`enroll_requested` 带 `review=1`）。同一会话 / 同一节点的接入类用 `tag` 合并。`category = test` 显示「Anycon 测试推送」
- **页面在后台**：页面转到后台（`visibilitychange` → hidden）满 30 秒就主动断开和 hub 的连接，回到前台再连（§ 6.4 的重连）。这样 hub 能看出这台浏览器「不在」，改为推送——手机上被冻结 / 挂起的页面收不到信封，但浏览器的网络层会替它回 WebSocket 的 ping，不主动断开的话 hub 会一直以为它在线、一条推送也不发。断开之前那 30 秒里收到 `notify` 信封、本浏览器**开着推送**（§ 4.9）且已授权通知时，页面经 service worker 的 `registration.showNotification` 弹同样的系统通知（同样的 `tag`），并且遵守账号偏好里这个类别的推送开关（读 `/api/me/notifications`，缓存 60 秒，读不到当作开）；本浏览器关了推送就不弹。已知限制：页面一转到后台就被系统直接冻结的（iOS 主屏 PWA 几秒内就会被挂起）计时器跑不到 30 秒，hub 会继续把它当作在线、不改发推送，直到系统真正关掉这条连接（`freeze` / `pagehide` 还没有接）；正在配对 / 接入或还有请求没回来时不断开，每 5 秒再试
- **应用内**：页面在前台时不弹系统通知，改为右上角 toast + 左栏会话条目的小红点；权限请求的 toast 带「查看」，去和推送同一个落点（`/inbox` 里那个会话最早的一条请求）；标了「待处理」的会话停下来时也弹 toast（§ 4.6.1）。「待处理」的数字一变，常驻外壳里的状态播报区（`role="status"`、`aria-live="polite"`）读出完整的一句话（「3 件事在等你」「现在没有等你的事了」），不是只读一个数字；启动和重连同步期间不播（§ 4.11），连着变几次合并成最后一句
- **角标**：`navigator.setAppBadge(「现在」段的条数)`（同样的数写在标签页标题前缀里，也是导航项和手机标签栏上的数：待答复的请求、计划、提问、接入请求、停下来的待处理会话、最近 7 天出错的会话、等待审批（缓存）的会话；还在跑的会话和未读不计入，§ 4.6.1、§ 4.11），**只算左栏节点过滤器勾选的节点**（旧版的角标算所有节点）；其他节点上有条目时只在节点过滤器按钮上有个小点。支持的平台上 PWA 图标显示数字。和导航项是同一份模型，只在输入变了或定时器到了才重算
- **接入相关**（ADR-36）：`enroll_requested` 和 `security` 没有 `session`，文案是「有设备请求接入 <节点名>」/「<节点名> 的安全提醒」，点击打开该节点设置的「接入」标签（`enroll_requested` 时自动弹出待批准请求的对话框）；同一节点的用 `tag` 合并。页面在前台时分别是 § 3.4 的横幅和 toast
- **声音**：默认关，设置里可开，只对 `permission_requested` 和 `enroll_requested`

### 9.1 命令面板

`⌘K` / `Ctrl+K` 开合；左栏的搜索按钮（宽屏左栏、没钉住时的窄条、手机「会话」标签页里各有一个）打开的是同一个面板。面板是一个贴近窗口顶部的对话框（不居中：搜索结果陆续出现时输入框不会跟着挪，手机软键盘也盖不住它）；关掉就清空查询，下次从空白开始。

**本地项**：不管输入什么都在本地算，不发请求。空查询列出全部，有查询时按文字（不区分大小写的子串）过滤标签和提示，最多 30 条：「新建会话」「新建项目」「克隆仓库」「打开已有目录」（页面在某个节点上时才有）、这个节点的项目、所有已配对的节点、所有本地已知的会话（按标题；全部节点的，不受左栏勾选影响，按最近活跃排序）。页面在会话页、会话没归档且节点在线时，最前面多一项「标记为待处理」（已标的是「取消待处理标记」，§ 4.6.1）。

**会话内容搜索**：查询去掉首尾空白后至少 2 个字符（按字符数，一个汉字算 1 个；只有 1 个字符时面板底部提示「至少输入 2 个字符才会搜索会话内容」）才开始。停手 300 ms 后，对**左栏勾选的、此刻在线（`ready`，§ 6.4）的节点并发**发 `session.search { query, limit: 20 }`（每个节点最多 20 条；超时 10 秒；不带 `project`，不翻页，想看别的就把查询写具体些），哪个节点先回就先显示。查询和结果走和别的 RPC 一样的 Noise 通道，hub 只看到元数据。daemon 搜什么、怎么匹配见 [protocol.md § 5.4](../protocol.md#54-会话) 的 `session.search`：用户消息和 assistant 文字，不含思考和工具输出；词按前缀匹配，没命中再按子串找；归档的会话也搜。

- 命中单独成一组「会话内容」，放在本地项下面。每条：会话标题（daemon 给的当前标题；空就写会话 id）、最多两行片段（命中词高亮）、时间（相对时间，悬停显示完整时间；是这段文字写入索引的时间）；勾了多个节点时标出节点名。顺序：按左栏勾选的节点顺序（也就是配对顺序），节点内按 daemon 给的相关度顺序，不跨节点重新排序。同一个会话可以有几条命中
- 没搜的节点：勾选了但不在线的，加上账号下这个浏览器还没解锁的节点（§ 4.3.1；它们不能勾选，也搜不了），在这一组最下面一句「未搜索（离线或未解锁）：A 和 B。」。没有一个节点能搜时，这一组只有这句话，不转圈
- 某个节点出错（`RpcError`、超时、返回的不是命中列表）：那个节点算失败，在组里说「无法搜索 A。」，别的节点的结果照常显示；形状不对的单条命中（缺字段、`seq` 不是非负整数……）丢掉，会话 id 已经属于别的节点的命中也丢掉（和会话列表一样，节点只能说自己的会话）
- 正在等：组里有「正在搜索会话内容…」和转圈；全部回来了还没有命中：「会话内容里没有找到。」
- **过期的响应一律丢弃**：查询变了（哪怕还在防抖里）或要搜的节点集合变了（某个节点上线 / 掉线），上一轮还没回来的请求作废，它们迟到的响应不会写进新一轮的结果；查询一变，旧结果立刻撤掉、回到「正在搜索」，不会留着对不上输入的结果让人点

**片段按文本显示**（片段来自会话内容，是对端给的）：daemon 的约定是 `snippet` 里除了包住命中词的字面 `<mark>` / `</mark>` 没有 HTML，会话文字里的 `<` `>` `&` 已转义成 `&lt;` `&gt;` `&amp;`（[protocol.md § 5.4](../protocol.md#54-会话)）。Web 不经过任何 HTML 解析器、不用 `dangerouslySetInnerHTML`：按字面 `<mark>` / `</mark>` 切开，每一段里把这三个实体各还原一次（一遍还原，`&amp;lt;` 得到的是 `&lt;`），再作为 React 文本节点渲染，只有 `<mark>` 里的那几段套一个 `<mark>` 元素；其余一切，包括没转义的 `<script>`、`<img onerror=…>`、带属性的 `<mark …>`，都只是显示成这几个字。没配对的标签不报错：多余的 `</mark>` 忽略，没收口的 `<mark>` 管到末尾。控制字符和双向控制符换成空格（不能让会话里的文字改写周围界面文字的顺序），一条片段最多显示 300 个字符，超出的截掉补 `…`。会话标题同样按文本显示、清掉控制字符。

**键盘**：输入框一直有焦点。`↓` / `↑` 在所有结果里移动（本地项在前、内容命中在后，到头回绕，移动时滚动保持选中项可见），鼠标移动也会改选中项；`Enter` 打开选中的那条，没动过就是第一条；`Esc` 关闭。输入法选词（组合输入）期间的 `↑` `↓` `Enter` 属于输入法，面板忽略。屏幕阅读器通过输入框的 `aria-activedescendant` 读到选中项。

**选中一条内容命中**：关掉面板，跳到 `/n/:node/s/:session?seq=<seq>`，会话页加载并定位到那条消息（§ 4.6）。

- 所有交互组件基于 Radix Primitives，保证焦点管理和键盘可达；手机标签栏是带名称的 `<nav>`，当前标签 `aria-current`；「待处理」的数字变化用状态播报区读出完整的一句话（§ 7）；处理完一条后焦点自动落到下一条（§ 4.11）；流式输出区域 `aria-live="polite"`，但 token 级增量不播报，只在 turn 结束时播报一句
- 字号三档，紧凑模式减小气泡间距
- 禁止页面缩放：默认关，保持系统的缩放行为。打开后，iOS 用 viewport 的 `maximum-scale=1` 止住聚焦输入框时的自动放大（Safari 为了无障碍不理 `user-scalable=no`），双指缩放靠拦 `gesturestart` / `gesturechange`，双击缩放靠 `touch-action: manipulation`；Android 用 `maximum-scale=1, user-scalable=no`（系统无障碍的「强制启用缩放」仍可覆盖）。桌面不显示这个开关

## 13. 预览

[ADR-39](../decisions.md#adr-39-预览-dev-servernoise-隧道里的端口转发)。两部分：Web UI 里的入口（§ 13.1），和预览 origin 上跑的**预览运行时**（§ 13.2）。两者是两份独立构建：Web UI 在 `web/dist`，预览运行时在 `web/dist-preview`，hub 分开嵌入、分开提供（[hub.md § 13.2](hub.md#132-预览域名上的-http)）。预览运行时的任何文件都不能进 Web UI 的构建产物和 service worker 预缓存。

### 13.1 Web UI 里的入口

**什么时候有**：`/api/config.preview_origin_template` 不为空，且节点 `capabilities.preview = true`。

**会话页的「预览」视图**：顶栏的视图开关在「聊天 / 改动」之后加「预览」（`main-view-preview`；不是 git 会话时只有「聊天 / 预览」）。和「改动」一样是占满顶栏以下的主视图，选择只对当前会话有效。

- **工具条**：端口选择（`preview-port`）、地址栏（路径，默认 `/`，回车跳转）、刷新、「在新标签页打开」（`preview-open-tab`）、「停止预览」（`preview.close`，确认后作废这个端口的全部票据，别的设备上开着的预览也会断开）
- **端口**：视图可见时每 5 秒调一次 `preview.ports { session_id }`，按 `port` 排序列出（`source = config` 的标「配置」）；另有「其他端口…」输入框，不在列表里的端口也能试（daemon 不允许时显示它的错误）。`detection = unavailable` 时提示「这台机器上没法探测端口，只能预览 `preview.allow_ports` 里的」。一个端口都没有时显示空状态：「agent 起了 dev server 之后这里会出现端口」
- **打开**：
  1. `preview.open { port, session_id }` → `{ label, ticket_id, psk, expires_at_ms, … }`
  2. `POST /api/preview/tokens { node, label }`，带本浏览器的设备 token（`Authorization: Bearer`）→ `{ token, origin, expires_at_ms }`
  3. 拼 `PreviewLaunch`（`v: 1`，`node_public` 取本地存的节点静态公钥，`expires_at_ms` 取两者较早的，`path` 取地址栏），JSON → base64url（无填充），URL 是 `<origin>/__anycon/enter#<…>`
  4. 内嵌：`<iframe src=… sandbox="allow-scripts allow-same-origin allow-forms allow-popups allow-popups-to-escape-sandbox allow-modals allow-downloads" referrerpolicy="no-referrer">`，**不给** `allow-top-navigation`。新标签页：`window.open(url, '_blank', 'noopener,noreferrer')`
- 拿到的 `PreviewLaunch` 只在内存里按（节点，端口）缓存，剩余有效期不到 10 分钟就重新走一遍；不写 IndexedDB。「刷新」总是重新调 `preview.open`（这个预览可能已经在别的设备上被停止，缓存的票据 daemon 不认了；票据还有效时 daemon 返回同一张），hub 令牌剩 10 分钟以上就沿用——每次刷新都换令牌会占满每设备 64 个的上限、挤掉这台设备上别的预览。URL 里的 fragment 带着密钥，不写日志、不进路由状态、不复制到剪贴板（「复制链接」只复制 origin + 路径）
- Web UI **不监听**来自预览 iframe 的 `message` 事件，也不往里发
- 手机上同样是主视图；工具条收成一行，「在新标签页打开」放在最显眼的位置（手机浏览器对第三方 iframe 里的 service worker 支持参差）
- 文案走 i18n（en / zh）

**节点设置的「预览」标签**：见 § 4.8。

### 13.2 预览运行时

在 `https://<label>.<预览域名>/` 上跑。构建：`vite build -c vite.preview.config.ts`，输出 `web/dist-preview`，`base` 是 `/__anycon/`。产物：`index.html`（引导页，**没有内联脚本**，同 Web UI 的约束）、引导脚本、`sw.js`（文件名固定，不带哈希）、`shim.js`（同样固定）、Noise wasm、`assets/*`。`sw.js` 是不含 `import` / `import.meta` 的单文件（Firefox 对 module service worker 的支持晚），wasm 由它显式按 URL 加载。依赖只有 `@anycon/protocol`，不引 React、不引 Web UI 的代码。

**引导页**（hub 对还没被 service worker 接管的页面请求都回它）：

1. 在 `/__anycon/enter` 且有 fragment：解出 `PreviewLaunch`，校验 `v === 1`、`label` 等于主机名的第一段、主机名第一段是合法 label；存进本 origin 的 IndexedDB（库 `anycon-preview`），**立刻** `history.replaceState` 抹掉 fragment；注册 `/__anycon/sw.js`（`scope: '/'`），等它激活，然后 `location.replace(launch.path)`。`path` 在 `decodePreviewLaunch` 里已经拒绝了 `\` 和控制字符（浏览器把 `\` 当 `/`、会吃掉制表符和换行，`/\evil.example` 会变成协议相对的地址）；跳转前再按本 origin 解析一次，解析出的 origin 不是自己、或者落在 `/__anycon/` 下就改成 `/`。没有 fragment 的 `/__anycon/enter`（刷新）跳到存着的 `path`
2. 别的路径：读 IndexedDB 里的 `PreviewLaunch`。有且没过期 → 确保 service worker 已注册、已激活，然后 `location.reload()`（用 `sessionStorage` 计数，10 秒内重载 3 次仍没被接管就停下，显示错误）；没有或过期 → 显示「这个预览要从 Anycon 打开」的说明页
3. 浏览器不支持 service worker（或者在第三方 iframe 里不让注册）：显示说明，带一个「在新标签页打开」的按钮。新标签页是另一个存储分区，看不到 iframe 里存的启动参数，所以按钮链接是 `/__anycon/enter#<启动参数>`（在内存里重新编码，`target=_blank`）
4. 文案按 `navigator.language` 选中文或英文，内置在运行时里

**service worker**（`sw.js`）：

- `install` 时 `skipWaiting`，`activate` 时 `clients.claim`
- **隧道**：每个 service worker 实例一条。第一次有请求时建立：从 IndexedDB 读 `PreviewLaunch`，连 `wss://<自己的主机>/v1/ws`，用 `token` 认证，等节点在线，按 [protocol.md § 11](../protocol.md#11-预览隧道) 握手。断线按 0.5 秒起、翻倍、封顶 10 秒重连；`auth_fail { invalid | version | protocol }`、close `4004`、`GOAWAY` 和握手被拒都是终态，记下原因，之后的请求直接返回错误页，不再重连（`auth_fail { quota }` 按退避重试；读不了的握手回复重试，连续 3 次后算终态）。隧道在请求发出之前断了，这个请求重试一次；已经发出去的请求失败就失败
- **拦截**：同 origin、路径不以 `/__anycon/` 开头的请求全部走隧道；跨 origin 的请求不拦。请求头取 `event.request.headers`（名字小写），加上 cookie jar 里匹配的 `cookie`；service worker 看到的请求头里缺了浏览器在网络层才加的那些，补上 dev server 常用到的：非 GET 请求的 `origin`、按 referrer 策略的 `referer`、`sec-fetch-dest` / `-mode` / `-site`、`user-agent`、`accept-language`、`content-length`。请求体先整个读出来（上限 16 MiB，超了回 `413`）再分段发
- **响应**：`new Response(流, { status, headers })`。`encoding = gzip` 时先过 `DecompressionStream('gzip')`。去掉 `set-cookie`（存进 cookie jar）和 `x-frame-options`；加 `content-security-policy: frame-ancestors 'self' <hub_origin>`（`hub_origin` 来自 `/__anycon/config.json`，读不到时只有 `'self'`；`'self'` 让 dev app 自己的同源 iframe 照常工作；dev server 自己的 CSP 头保留，浏览器取交集）。`204` / `304` 等没有正文的状态码不带流
- **注入 shim**：导航请求（`request.mode === 'navigate'`）返回 `text/html` 时，在第一个 `<head>` 标签之后插入 `<script src="/__anycon/shim.js" data-cookies="…"></script>`；没有 `<head>` 就放在 `<html>` 之后，再没有就放在 doctype 之后，都没有才放最前面（放在 doctype 前面会让页面进怪异模式）。`data-cookies` 是这个路径上 cookie jar 里非 HttpOnly 的 cookie（和 `document.cookie` 同样的格式，HTML 转义）。流式处理，只缓冲到找到插入点为止（最多 64 KiB）。UTF-16 / UTF-32 的页面不注入
- **HTTP 缓存**：浏览器不会把 service worker 合成的响应放进 HTTP 缓存，所以 service worker 自己做：`GET` 且状态 200、带 `etag` 或 `last-modified`、没有 `cache-control: no-store` 的响应存进 Cache Storage（`anycon-preview-http`，总量 200 MiB，超了按最近使用删；导航、`Vary` 里有 `accept-encoding` / `origin` 以外的头、单个超过 16 MiB 的不缓存）；下次同一 URL 的请求带上 `if-none-match` / `if-modified-since`，收到 `304` 就用缓存。`cache-control` 带 `immutable`（或 `max-age` 未过期）的直接用缓存，不走隧道。请求的 `cache` 是 `no-store` / `reload` 时绕过缓存
- **cookie jar**：存 IndexedDB。解析 `Set-Cookie` 的名、值、`Expires`、`Max-Age`、`Path`、`HttpOnly`；`Domain` 忽略（一律只属于本主机）、`Secure` / `SameSite` 忽略。请求时按路径匹配加 `cookie` 头。有非 HttpOnly 的 cookie 变化时 `postMessage` 给本 origin 的全部页面
- **错误**：隧道不可用时，导航请求返回一页 HTML 说明原因（节点离线、预览已过期 / 被关闭、端口不再允许……），终态时提示「回到 Anycon 重新打开」，可恢复的（节点离线、正在连接）5 秒后自动重试（`<meta http-equiv="refresh">`，没有内联脚本）；子资源请求返回 `502` 纯文本
- **和页面之间的消息**：页面 → service worker：`ws.open` / `ws.send` / `ws.close`、`cookie.set`、`cookies.sync`、`keepalive`；service worker → 页面：`ws.open` / `ws.message` / `ws.close` / `ws.error`、`cookies`（非 HttpOnly cookie 的快照）。只收本 origin 页面发来的
- **保活**：页面里的 shim 每 20 秒 `postMessage({ type: 'keepalive' })`，有预览页开着时 service worker 就不会因为空闲被浏览器回收（否则经它转发的 WebSocket 会断）。被回收了也能恢复：下一个请求重新建隧道，dev app 的 WebSocket 客户端照常重连

**shim**（`shim.js`，作为页面的第一个脚本执行）：

- **WebSocket**：把 `window.WebSocket` 换成一个兼容的类。同 origin 的 `ws:` / `wss:` 地址经 service worker 走隧道（`navigator.serviceWorker.controller.postMessage({ type: 'ws.open', id, url, protocols })`，service worker 用 `client.postMessage` 回 `ws.open` / `ws.message` / `ws.close` / `ws.error`）；别的地址用原生的。实现 `readyState`、`protocol`、`binaryType`（`blob` / `arraybuffer`）、`bufferedAmount`、`send`（string / ArrayBuffer / TypedArray / Blob）、`close`、`on*` 和 `addEventListener`
- **service worker**：`navigator.serviceWorker.register` 改成直接拒绝（`console.warn` 说明预览里不支持 dev app 自己的 service worker），`getRegistration` / `getRegistrations` 返回空（dev app 常见的「注销全部 service worker」清理代码删不掉预览的那个）。否则 dev app 会顶掉预览的 service worker
- **cookie**：**不用**浏览器原生的 cookie。原生 cookie 会随 `/v1/ws` 和 `/__anycon/*` 的请求发给 hub，hub 就看到了 dev app 的 cookie。shim 在 `document` 上定义 `cookie` 访问器，背后是页面内的一份 cookie 表：初值来自 `data-cookies`，写入时同时 `postMessage` 给 service worker 存进 cookie jar（这样页面自己设的 cookie 也会随请求发出去），收到 service worker 的 `cookies` 快照时更新。HttpOnly 的 cookie 只在 cookie jar 里，页面看不到，和真实浏览器一样
- 尽量小，不依赖任何库

### 13.3 已知限制

- dev app 里写死的 `http://localhost:<端口>` 绝对地址不工作；相对地址和同 origin 的绝对地址都可以
- 硬刷新（绕过 service worker）会先回到引导页，再自动重载一次
- 浏览器在第三方 iframe 里不允许注册 service worker 时，内嵌显示说明，要用新标签页
- dev app 的 CSP 用 `nonce` / `strict-dynamic` 而且没有 `'self'` 时，注入的 shim 会被拦（WebSocket 不走隧道、cookie 不同步）
- 隧道重置时已经发出去的请求失败，不重试
- 经隧道的 WebSocket 的 `bufferedAmount` 是估算值
- 预览 origin 的 IndexedDB 里有令牌和票据密钥，dev app 的 JS 读得到（[ADR-39](../decisions.md#adr-39-预览-dev-servernoise-隧道里的端口转发)「代价」）

> **尚未实现的**：清单（`/todos`、清单页、单项详情）、「记一项」（底栏「＋」、`C`、`/capture`、分享入口、命令面板入口）、空间切换、「待验收」「稍后」两段和对应条目、验收页、规则页、分身页、手机底栏的「清单」和「＋」位置、`turn_finished` 落到验收页的通知落点、`E` / `X` 等清单键、会话页和左栏的清单来源标记。这些在界面上没有任何入口。

### 14.1 为什么要重排

现在的界面围着「会话」转：用户发起每一件事，看着它流式输出，点审批。有了清单和分身之后，用户的位置变了：

- 很多活不是他当场发起的，也不是他看着做完的。他要做的是**把事交出去、处理等他的事、偶尔看一眼分身在干什么**。
- 「等他的事」不再只有权限请求：还有计划、分身的提问、做完等验收的改动、待确认的规则、接入请求、卡住的项。散在各个会话页里就找不到了。
- 分身派出的会话他多半不会打开，都摆进左栏的会话树，树就没法看了。
- 家里和公司的节点要分开看（[daemon.md § 21.7](daemon.md#217-多个节点)）。

所以改三件事：**首页从「项目树」换成「待处理」**；**记一项要比开一个会话还快**；**全局先选空间，再看内容**。会话页本身（§ 4.6）不动。

目标（验收时逐条量）：

| 场景 | 目标 |
|---|---|
| 手机上记一项 | 从主屏图标到记完：长按图标选「记一项」或点底栏「＋」，输入，发送。不要求填任何别的东西 |
| 桌面上记一项 | 任何页面一个快捷键，输入，回车；不离开当前页面 |
| 从通知到处理完一条审批 | 点通知 → 看到这条请求的详情和按钮 → 点一下。两次点击 |
| 把等我的事清完 | 在「待处理」一页里做完，不用进会话页（验收改动除外） |
| 打开应用 | 先显示本地缓存的待处理和清单，再同步；节点全离线也能看、能记 |

### 14.3 空间

左栏顶部的节点过滤器升级为**空间切换**：列出各个分组名（[daemon.md § 21.7](daemon.md#217-多个节点)，比如「家里」「公司」）和「全部」，展开后仍可像现在一样单独勾选节点。没给任何节点设分组时，它就是现在的节点过滤器。

- 空间对四个去处同时生效：待处理、清单、会话树、分身都只显示所选空间的节点。选择记在这台设备上。
- 顶栏一直显示当前空间的名字。分组不带标记色（§ 14.13）。
- 记一项时缺省落在当前空间里上次用的那个节点；选了「全部」时用上次记到的节点，并在输入条上写明是哪个节点。
- 从通知或链接打开的内容不在当前空间时：照常显示，顶部一行说明它属于哪个空间，带「切换到这个空间」；不自动切换。
- 应用角标和「待处理」的数字只算当前空间。别的空间有「现在」类的事时，空间切换按钮上有一个点。

### 14.4 待处理

所有等用户的事放在一个队列里，按「不处理会卡住什么」分三段：

| 段 | 类型 | 来源 | 行内能直接做的 | 从哪一步有 |
|---|---|---|---|---|
| 现在 | 权限请求 | `permission.list`（`tool` / `mode_change` / `other`） | 展开看完整详情，按请求给的选项答复 | 1 |
| 现在 | 计划 | `kind = plan` | 展开看计划，开始实施 / 继续规划（带意见） | 1 |
| 现在 | 提问 | `kind = question`；分身的提问 | 选项直接点，自由输入就地填 | 1 / 4 |
| 现在 | 接入请求 | `node.enroll_list` | 批准 / 拒绝（§ 4.3.2 的对话框） | 1 |
| 现在 | 你标了「待处理」的会话 | `follow_up` 且已经停下来的会话（§ 4.6.1；归档的不算，已经在等审批的不重复列） | 打开、已处理（清掉标记） | 1 |
| 现在 | 出错、卡住 | 没归档、最近 7 天内出错的会话（`status = error`，按 `updated_at_ms` 算）；清单项失败到上限或长时间没进展 | 打开、归档；清单项另有重试 | 1 / 4 |
| 待验收 | 做完的清单项 | `state = review` | 看摘要和改动统计；通过 / 再改 / 打开改动（§ 14.7） | 2 |
| 稍后 | agent 记的项 | `unreviewed = true`（[daemon.md § 21.2](daemon.md#212-todo)） | 收下 / 丢掉（`state = dropped`，不物理删除） | 1 |
| 稍后 | 待确认的规则 | 档案里状态是待确认的 | 确认 / 改一下再确认 / 否决；可以多选一起处理 | 3 |

- **出错的会话怎么离开这里**：`error` 是会话的持久状态，没有「已读」。用户重新发了消息或重启了会话（状态变了）、把它归档、或者过了 7 天，它就不在这一段里；行上的「归档」就是「我知道了」。不为它另存一个「已忽略」的标记：那只能存在一台设备上，换台设备又冒出来。`interrupted`（daemon 重启留下的）不算等用户的事，下一次发送会自动续上。
- **排序**：「现在」段按到期时间（`expires_at_ms`）先后，没有到期时间的按等待时长；其余按时间。
- **和会话上的「待处理」标记是一回事**：会话上的「待处理」（§ 4.6.1，[ADR-53](../decisions.md#adr-53-会话标注待处理是布尔标记未读是已读水位都和归档分开)）说的就是「它在待处理这一页里」。标了的会话停下来就进「现在」段，等得最久的在前；行上的「已处理」清掉标记。还在跑的（「完成后提醒」）不在这里，在「进行中」。未读（红点）不进这一页：它只管「看过没有」，不是等用户的事。
- **数字**：导航项和应用角标（§ 7）只算「现在」段。只算左栏节点过滤器勾选的节点（§ 14.3 的空间到来时改为当前空间），别的节点上有「现在」类的事时，节点过滤器按钮上有个小点。包括：待答复的请求、计划、提问、接入请求、停下来的待处理会话、最近 7 天出错的会话、会话摘要说在等审批但请求还没到的会话（缓存）。待验收和稍后各自在段标题上有数字，不进角标：它们不卡着正在跑的活。
- **权限请求在这里和在会话页里是同一个卡片组件**，显示同样完整的内容（命令、工作目录、节点、所属会话和清单项）。没有「不看详情就批准」的入口：行上的按钮只在详情展开时出现，桌面上选中一行即展开在右半边，手机上「现在」段的第一条默认展开。
- 处理完一条，焦点自动落到下一条，不用回到列表再点。全部清完时这一页显示「没有等你的事」，下面是「进行中」：正在跑的会话和清单项，每行一个状态，点进去看。
- 「进行中」平时折叠成一行（数量），不和等用户的事抢位置。
- § 3.4 第 3 条的接入横幅保留（它要在任何页面都看得到）；左栏原来的「待审批」和「待处理」两个置顶组并入这一页，左栏不再重复列；取消固定后窄条上的两个个数合成「现在」段的一个数。

### 14.5 记一项

入口，全部落到同一个输入条：

| 入口 | 说明 |
|---|---|
| 手机底栏「＋」 | 底部弹层，输入框已聚焦、键盘已弹起 |
| 桌面 `C`（焦点不在输入框时）、左栏「＋」 | 屏幕顶部的一行输入条，不遮当前页面，`Esc` 关掉 |
| 命令面板 | 输入之后 `⌘Enter`：把这段文字记成一项；列表第一条也始终是「记到清单：<输入的文字>」 |
| 会话页 | 选中一段文字后的浮动菜单、消息的「…」菜单里的「记到清单」；正文带上那段文字和回到这条消息的链接 |
| 主屏图标长按 | PWA manifest 的 `shortcuts`：「记一项」→ `/capture`，「待处理」→ `/inbox` |
| 从别的应用分享 | manifest 的 `share_target`：`action: /capture`、`method: POST`、`enctype: multipart/form-data`。service worker 拦下这个 POST，把 `title` / `text` / `url` 暂存到 IndexedDB，回 303 到 `/capture`，页面取出来填进输入条后删掉。分享的内容不进 URL（URL 会留在 hub 和它前面反代的访问日志里，配对短码放在 fragment 里是同一个理由）。只有支持它的平台有这个入口 |

- **service worker 没接管时的分享**（刚安装还没激活、被浏览器回收）：那一次 POST 会发到 hub。hub 对 `POST /capture` 回 303 到 `/capture`，不读请求体、不存、不进日志；页面打开的是空的输入条，那一次分享的内容丢了。也就是说这种情况下分享的文字经过了 hub，隐私模型里照实写（[architecture.md § 5.6](../architecture.md#56-威胁模型)）。
- **只要求一行字。** 第一行是标题，换行之后是正文。发送后弹层留着、清空，可以接着记下一条；提示条里有「撤销」。
- 输入框上面一排可选的小项，都有缺省值，可以完全不碰：节点（§ 14.3 的缺省）、项目（缺省不选）、期望时间。第 4 步多一个「交给分身 / 我自己做」，缺省跟随上次的选择。
- 节点离线照常能记：这一项标着「未同步」，节点回来后自动补上（[daemon.md § 21.6](daemon.md#216-节点离线)）。
- **对分身说话就是记一项。** 没有单独的「和分身聊天」窗口：想让它做什么，记一项交给它；想知道它在干什么，看清单和运行记录。

### 14.6 清单和单项

**清单页**：按状态分组，顺序是 等你决定、待验收、处理中、还没开始、已关闭（折叠）。第 1 步没有派发，「等你决定」和「待验收」没有东西会进去，这两组和对应的状态选项到第 2 步才出现；第 1 步只有后三组（`waiting` / `review` 的项归在「处理中」）。「已关闭」展开时才向节点要已关闭的项，一页页往下翻。每行：标题、项目和节点（多节点时）、谁在处理（我 / 分身 / agent 的图标）、关联会话的实时状态点、期望时间。顶部一条分身状态（第 4 步起）：处理中几项、今天的预算用了多少、暂停按钮。

- 手机上行向左滑是「完成」，带 5 秒的撤销提示；每个滑动动作在长按菜单和详情页里都有对应的按钮，不是唯一入口。权限请求没有任何滑动操作。
- 桌面上 `J` / `K` 上下移动，`E` 完成，`Enter` 打开，`X` 多选后一起改状态。
- 筛选：项目、谁在处理、来源（我记的 / agent 记的）。不做拖拽排序。

**单项详情**（桌面在右半边，手机是二级页）是一件事的全部经过：

```
修 WS 重连                                [待验收]
api-server · mac-studio · 分身处理

要做的事（正文，可编辑）

经过
  10:02  你记下这一项
  10:03  分身派给 Claude Code（按规则「先写失败的测试」）
  10:04  ▸ 会话：修 WS 重连        运行中 → 已结束
  10:21  改动 6 个文件 +48 −12，测试通过
  10:21  等你验收

[ 通过 ]  [ 再改改… ]        打开改动 →
```

- 「经过」里的每一行都能点：会话、那条规则、那次运行记录。分身的每个决定都写着依据。
- 分身或 agent 的提问出现在「经过」的末尾，就地回答。回答框下面有一个勾选「以后都这样」，勾上就同时生成一条规则（手动勾的直接生效，ADR-54 第 3 条）。
- 还没开始的项，主按钮是「让 agent 处理」（第 2 步；选 agent、模型、工作位置，缺省值同新建会话页）和「交给分身」（第 4 步）。
- 你在分身派出的会话里发了消息，这一项就标成「你接手了」，分身不再碰它，直到你再交回去。

### 14.7 验收

验收是这套界面里最值得做好的一步：分身省下的时间，就花在这里。

- 验收页先给**结论**，再给细节：做了什么（agent 最后一段话）、改了哪些文件和行数、测试或检查的结果（agent 说了才有）、它中途被审查器拒绝过什么。然后才是文件列表，点开看 diff（就是会话页的「改动」视图，§ 4.6）。
- 三个动作固定在底部：**通过**（这一项完成）、**再改改…**（一个输入框，写的话作为消息发进那个会话，这一项回到处理中）、**不要了**（这一项标为不做，问一句要不要连 worktree 和分支一起删）。
- 通过之后接着问下一步，都是可选的快捷消息：让 agent 提交、推送并开 PR。分身派出的会话默认不能自己 push 和开 PR（ADR-54 第 5 条），这里是把那一步交回给人的地方。
- 手机上 diff 是一个文件一屏、上下滚动，文件之间左右切换；底部操作条一直在。

### 14.8 分身和规则

**分身页**（`/twin`）：当前空间里每个节点一张卡。

- 状态：开着 / 暂停 / 预算用完 / 节点离线；正在处理的项；今天用了多少预算；最近一次唤醒的时间和原因。**暂停**是卡片上最显眼的按钮，一个空间可以一起暂停。
- 「它会怎么做」：试跑的结果，每项一行（派发 / 问你 / 跳过，以及理由），下面是「就这么办」。第一次打开分身之前，界面先带着用户试跑一遍。
- 运行记录：按时间倒序，每次唤醒一行（原因、处理了几项、花了多少），展开看它对每一项的决定和依据。没事可做的唤醒折叠成一行「N 次无事」。
- 范围和预算：能进哪些项目、用哪个 agent / 模型 / 模式、同时几个会话、每天的预算；判断后端的选择。

**规则页**（`/rules`）：两个标签，待确认和已生效。

- 待确认的每条：规则的文字、它从哪来（点开是那个会话里的那几条消息）、范围（只在这个节点 / 同组节点；全局 / 某个项目）。动作：确认、改一下再确认、否决。可以多选。
- 已生效的：最近用到的时间、已用字数 / 上限、过期的另起一段。范围是同组节点的规则旁边有同步状态；各节点不一致时页面顶部给出「对齐」。
- 在审批卡片和问答的答复框旁边有「记成规则」：把这次的选择写成一条规则，文字可改，直接生效。

### 14.9 会话页和左栏的改动

- 从清单项来的会话：顶栏多一个 chip，写着那一项的标题，点了回到单项详情；右栏信息面板里列出它。
- 左栏的项目下面，从清单项来的会话不逐条列，收成一行「来自清单 N」，点开才展开；有等用户的事的会话照常浮在「待处理」里。手动开的会话和现在一样。这个折叠可以在外观设置里关掉。
- 左栏底部的分身状态条（第 4 步）：处理中几项、等你几项、是否暂停；点了去分身页。

### 14.10 通知

| 类别 | 文案 | 点开落在 |
|---|---|---|
| `permission_requested` | 现状 | `/inbox`，定位并展开那一条（不再是会话页；详情和按钮都在这里，旁边有「打开会话」） |
| `turn_finished` | 会话属于某个清单项时：「<项的标题> 做完了，等你验收」；否则现状 | 清单项的验收页；否则会话页 |
| `error`、`session_idle`、`follow_up` | 现状 | 现状 |
| `enroll_requested`、`security` | 现状 | 现状 |
| 分身在等你回答（第 4 步的新类别） | 「分身有个问题：<项的标题>」 | `/inbox` 里的那一条 |

- 通知上不放「允许 / 拒绝」按钮：service worker 手里没有解密后的请求详情，在通知上答复等于不看内容就批准。目标是点开之后一步到位，而不是省掉看这一眼。
- 文案第二行除了节点名再带上空间名；通知的 `tag` 按会话或清单项合并，规则同 § 7。
- 待确认的规则、agent 记的项不推送，只进「待处理」的稍后段。
- 应用内（页面在前台）：现状的 toast，点了去同样的落点；「待处理」的数字变化用一个状态播报区读出完整的话（「3 件事在等你」），不是只读一个数字。

### 14.11 键盘（桌面）

在 § 9 的基础上增加；焦点在输入框里时单字母键都不生效。

| 键 | 作用 |
|---|---|
| `G` 然后 `I` / `T` / `S` / `A` | 去 待处理 / 清单 / 会话（回到上次的会话）/ 分身 |
| `C` | 记一项 |
| `J` / `K` | 列表里下 / 上一条 |
| `Enter` | 打开选中的一条（待处理里是把焦点移进详情） |
| `E` | 清单：完成选中的项 |
| `⌘⇧A` / `⌘⇧D` | 现状，在待处理页作用于选中的那条权限请求 |
| `⌘Enter`（命令面板里） | 把输入的文字记成一项 |

现有的 `[` / `]`（上 / 下一个会话）不变。
